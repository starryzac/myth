# MVP-401 资金边界首页

状态：COMPLETE（定向验收）。2026-10-05，完成计数18/92；初版25项和完整版均未完成，目标保持ACTIVE。

首页显示现金、自主安全闲置、目标归属、自主配置本金、今天保护层、下一组义务、91日限制点及介入状态。金额缺证据时为null，页面显示“待核验”；目标现金保护明确包含待归属余额。未来收入不扩大今天边界，归属本金与自主配置的重叠不会再次相加。

## 实现与设计

原financial-v1与展示明细共享一次纯core计算，30组冻结旧输出及hash保留。GET /api/v1/dashboard在可信用户首次读取前建立同一REPEATABLE READ / READ ONLY事务。完整曝光、银行投影、收入来源、当前审计epoch和各动作原锚点在同一来源基准核验；没有跨请求缓存或只读时创建金融对象。列表有total/has_more，完整金融来源预算先检查再加载，不能截断后求和。

主要文件：domain/boundary.py、boundary_details_types.py；services/dashboard*.py及api/v1/dashboard.py；Web App.tsx、styles.css、api/dashboard.ts与money.ts。结构和口径见[架构](../architecture/dashboard.md)。真实生成的OpenAPI与schema.d.ts随本项更新。

为完成真实工资/目标/消费/赎回链，增加严格外部银行事实、bank posting v1/v2及0007迁移。银行独立事务接受两条守恒经济腿，应用投影和审计在另一事务。首键与原事实绑定，同ref换键冲突；UNKNOWN只补同一原件投影，不重新发银行腿。消费FIFO先用已验证可用收入，再用已证明未跟踪现金，不能释放目标归属、收入claim或执行预留。两笔先后UNKNOWN须按真实现金前缀恢复；本次真实RED发现第一笔被第二笔阻塞后，最小修改仅允许内部完整守恒核验接受仍待投影原事实，公共默认核验仍拒绝缺口。

fresh seed保留原mvp-301-v6金融历史，在genesis前建立可信FIFO收入位置与CLEARING开账。旧reset key仍原响应零写。原exposure-v1测试显式选择首次legacy初态，原金融断言保持。新增零CASH的转账夹具仅追加真实scope证明，原来源/资金/70断言不变。

审计capture原先重复严格构建与深序列化同一原件。新encode_subject_original完整校验一次，即时生成原text与原namespace hash；公开hash/text仍重新验证调用者DTO，嵌套可变数据不能借frozen标记绕过。旧canonical、版本、用户/epoch、预算、错误语义和金融校验保持。30项新编码节点与冻结原实现逐字节对照证明此接缝。

## 耗时与限制

本项只做风险驱动定向验收，没有全量；两个版本全量节点规则见[验证表](../spec/verification-map.md)。没有真实银行、外部发布、消息发送或PR。

阶段计时证明瓶颈不在建库/迁移/种子（约0.2/1.1/1.8秒）。最后一轮目标配置26.781秒、申购21.547秒、赎回19.719秒，而后期首页读取82.047/89.485秒；整条黄金节点802.35秒。干净同步资金profile指出capture重复构建，已按原字节协议优化；GET的旧asyncio调用树污染，不能当精确累计归因。一次编码优化没有解决剩余读取开销，后续单独处理同一verifier调用内重复索引/编码，保留预算优先与篡改校验；不能宣称达到延迟SLA。原计划没有毫秒阈值，后续404连续演示与504离线三链必须实际验证。
