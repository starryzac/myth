# MVP-205 安全恢复引擎

状态：COMPLETE（2026-10-04）。前置MVP-204提交ca43d0f。完整check 20261003T233659Z-bec8c501 exit0：850后端、4前端、1Edge通过，11条子命令全部成功，129个源码/配置摘要运行前后完全一致。

依据初版MVP-205和[ADR0008](../adr/0008-evidence-bound-safety-recovery.md)实现合成模拟环境中的整仓无损恢复、独立银行经济分录、应用对账、回执和本地通知。有损报价生成明确后果的ASK_ONCE提案；确认后有损执行仍是MVP-301的必需范围。

## 实现与关键选择

- 纯域按T0/T1和稳定仓位身份规划，比较全部273个对应检查点，要求逐点不劣且至少改善一个负点；允许部分恢复，停止无助于缺口的额外赎回。原本金返还事件被替换，收益不计入可用本金。
- T0使用明确到账后的反事实快照；T1仅投影未来到账，实际现金不提前增加。保留actual、projected、未覆盖点和预计持续安全起点，纯计划不宣称RECOVERED。
- 新自主请求同时检查原购买与当前最新授权、原产品版本、金额、归属、锁定、赎回时间和完整来源。人工旧v1仓不能借新权限/条款自动赎回。有费用或损失即ASK_ONCE。
- 新增银行请求与posting两表，18表迁移0003；请求经济载荷不可修改，posting不可UPDATE。可信模拟开户来自4个非信用卡账户和3仓的固定指令，正常结算不复制可编辑应用余额作为银行真值。
- 应用请求提交→独立银行提交→新应用事务对账。本金减少和现金增加两腿守恒且各自唯一；同键、同仓、故障恢复均保留原经济操作。多仓投影按银行现金账本序号消费，后仓被拒绝不阻止前仓已发生效果对账。
- 自然到期按原完整固定合同结算，当前撤销不会取消既有本金回款。目标本金返还原目标，累计归属和月贡献不变；已有收入lot的消费、归属、预留和可用金额不被重置，本金返还不是新增收入。
- 曝光v1保留原模拟进口边界，不解释恢复状态；恢复后v2包含完整银行请求/posting集合。202/203/204/205读取v2时核验独立账本与应用投影。恢复入口即使读取v1也核验独立开户账本。
- HTTP只接收非空白、最长160字符的幂等键，不接收客户指定的用户/金额/仓位/权限/时钟。GET始终只读，即使T1已到期也不结算。历史plan与当前实际风险分开，旧无动作记录不能沿用过期的“无需恢复”结论。
