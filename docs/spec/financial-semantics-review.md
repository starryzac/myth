## 2. 必须先处理的规格张力

M:484–489 要求“任何时点的可支付现金不得低于该时点剩余受保护需求”，但没有定义“剩余需求”究竟是：

1. 未来 90/365 天全部未付义务总额；
2. 还是各日期前必须可支付的需求，以及始终须保有的现金底线。

若采用第一种解释，全部远期义务今天就必须由现金覆盖。未来既有本金到期不能用于远期义务的期限匹配，保护资金也不能进行期限配置。这比 F:473“所有硬义务在其截止日前均有可用现金覆盖”、F:519“目标内可改变资产放置”、F:591–599“定存梯度”更严格。

**决策建议，尚未采纳：** 在 MVP-202 前通过 ADR 区分保护资金归属与支付流动性。保护资金绝不当闲钱；只有对应资产策略明确授权时，才可保留归属进行期限匹配。未经决策，不得在代码中默默混用两种含义。

## 3. 严格字面现金保护公式

本节给出第一种解释的一致形式，可用于检查重复计数；不宣称它是最终实现选择。

设：

- `C(t)`：时点 t 的实际或保守投影可支付现金；不含尚未到账的资产本金。
- `U(t)`：仍未支付、仍有效的固定义务金额总和。
- `L(t)`：已确认生活预算尚未消耗部分。
- `E(t)`：必须保持的应急现金。
- `G_cash(t)`：C(t) 中已经归属目标的现金部分。
- `M_g(t)`：目标 g 本期尚未完成的最低贡献。

```text
M_g(t) = max(0, min[g, period] - contributed[g, period])

S(t) = C(t) - U(t) - L(t) - E(t) - G_cash(t) - sum_g M_g(t)

严格现金保护条件：对每个检查点 t，S(t) >= 0。
```

也可以先从 C 中排除目标现金，然后不再减 G_cash；两种记账口径只能选一种。目标资金已经买成资产的部分本来就不在可支付现金 C 中，不能再把全部目标资产金额减一次。目标整体归属保护应另行检查。

若唯一变化是支付已纳入 U 的义务 D(t)：

```text
C(t) = C(0) - D(t)
U(t) = U(0) - D(t)
```

现金与未付义务同步减少，保护余量不变。错误做法是从现金扣已支付义务，却继续保护原始全额。

### 3.1 严格模式为何可能得到相同产品上限

若所有未来支出都已包含在初始 U(0)、生活预算和其他保护金额中，之后只发生这些支出，没有新增未纳入的承诺，则现金减少与剩余保护减少互相抵消；既有资产本金到期还会增加现金余量。

因此各产品的金融配置上限相同可能完全正确；风险、锁定、起投和用户授权仍可令个别产品上限更低或为零。不能为了展示不同产品上限而人为制造不一致公式。

## 4. 建议的统一模型：资金归属与现金流分开验证

本节是第二种解释的实现建议，尚未成为 MVP-202 规格。

为资金保留范围 `s`，例如通用未归属资金、某目标资金、某受保护预算。保护资金与普通闲置资金不互相混用；内部资产放置也不能改变 owner/goal 归属。

对按时间和事件先后排序的检查点 k：

```text
B[s,k] = C[s,0]
         + sum(principal_available[s,j], j <= k)
         + sum(authorized_in[s,j], j <= k)
         - sum(external_payment[s,j], j <= k)
         - sum(authorized_out[s,j], j <= k)
```

其中：

- 未来工资、奖金、预测回款全部为零。
- `principal_available` 只表示已拥有资产在有证据支持的到账时点可用的本金。它是现有财富变现，不能在今天提前显示为现金。
- `authorized_in/out` 表示合法内部范围调拨。对合并现金它们相互抵消；对各归属范围须分别记账。
- `external_payment` 表示该范围承担的、按日期规范化后的独立付款；不重复产生同一义务。

候选从范围 s 购买产品 p，金额 x。截至检查点 k，已合法、无损恢复成现金的本金比例为 `r[p,k]`：

```text
C_candidate[s,k] = B[s,k] - x * (1 - r[p,k])
```

若范围 s 的当时现金底线为 `F[s,k]`：

```text
对所有检查点 k：C_candidate[s,k] >= F[s,k]

Q_finance[s,p]
  = min over k where r[p,k] < 1:
      floor((B[s,k] - F[s,k]) / (1 - r[p,k]))
```

计算需采用整数分及精确定点/有理数处理，不能以二进制浮点误差突破硬边界。当 `r=1` 时，候选已不减少现金，但该检查点的基础现金安全条件仍必须通过；不能直接跳过基础可行性检查。

金融上限还须与以下限制取交集：

- 当下该范围实际可购买的现金；
- 用户总管理剩余额度和单次上限；
- 产品容量、起投金额、风险、锁定、赎回权限；
- 对应资金归属范围的资产授权；
- 若属于目标新增贡献，真实新增且未归属资金来源的剩余额度。

候选申购后、任何本金返还前必须有检查点；不能把 T0 等同于没有现金占用，跳过中间可能存在的现金缺口。

### 4.1 不能把两种需求表达加在一起

在这个建议模型中，未来义务作为对应日期的 `external_payment` 出现。不能又把同一笔全部剩余义务加进现金底线 F。F 只包含没有通过该支出事件表达的现金底线。

资金归属账负责“不把受保护资金当闲钱”；现金流账负责“在应付日期拿得到现金”。两者分别验证，不能用总资产充足替代按日期可支付，也不能用按日期可支付替代目标归属权限。

`max_allocatable_by_product` 必须明确 scope。目标内可配置资产的额度不能混入通用 `safe_idle_cents`。如果现有接口只提供通用闲钱的产品上限，目标资产服务应另有范围明确的结果，不能静默合并。

### 4.2 已有缺口不是零额度就算安全

基础检查点若已经不安全，不能只做 `max(0, cap)` 并丢掉负缺口。应保留原始缺口、冲突或流动性风险与原因。

增加新投资风险的动作不能自动执行。改善状态的恢复动作需要独立、明确的恢复状态语义；在独立账本回执确认完全恢复以前，不能显示“已安全”。具体恢复过程中能否执行部分改善动作须写 ADR，不能通过改写普通投资安全门处理。

## 5. 防止重复计数的建模规则

以下观点可供 MVP-101 建模参考，不改变原计划要求。

| 对象 | 一致处理方式 | 常见错误 |
|---|---|---|
| 义务、账单、政策 | 同一经济义务只有一个 occurrence，例如政策＋账期；银行账单更新已知金额和证据。 | 周期政策和真实账单各生成一次同额付款。 |
| 已发生交易 | 快照带明确时间/流水水位；已计入余额的历史交易不再次进入未来扣款。 | 用当前余额又减去已经记账的全部流水。 |
| 生活准备金 | 一次窗口预算按实际消耗减少；持续滚动底线与持续消费只有在明确授权的持续补充语义下共同存在。 | 固定保护初始完整预算，同时把同一窗口支出再扣一遍。 |
| 准备金历史估计 | 仅用户确认类别，排除明确一次性支出；一次性支出仍真实影响账户现金。 | 从估计排除一次性支出后连实际现金影响也删除。 |
| 信用卡 | 不把消费与账单还款作为同一历史生活消费统计两次；当前账单对应过去消费，未来生活预算对应未来窗口。 | 要么历史消费双算，要么误以为未来生活预算与旧账单必然重复而删掉真实义务。 |
| 目标月度贡献 | [min,target,max] 是本期累计额度，减去本期已贡献后得到剩余额度。 | 每次重算重新贡献整个 target 或保护整个 min。 |
| 目标内部划转 | 本人账户合并现金不变，目标归属增加；源范围现金减少，目标范围增加。 | 合并现金扣一次，再从余额减目标归属一次。 |
| 目标买资产 | 只改变资金放置，不新增目标贡献，不产生新收入。 | 买资产时再次增加目标进度或贡献额。 |
| 新增资金 | 真实已到账且尚未消耗的来源 lot/event，重试不能重复消费。 | 把所有当前余额或每次重算都当新增收入。 |
| 本金到期 | 默认只把已有资产本金变为现金；不视为新增收入来源。 | 定存反复到期/续作造成目标反复“新增贡献”。 |

最后一项新增资金来源的精确资格须 ADR 明确；本文建议不能被解释为已新增一条原计划不存在的授权。

## 6. 到期、T+1 与有损提前支取

计划明确 M:488、F:477–478：赎回或到期可用以前不能计入现金；有损提前支取资产不能自动充当安全现金。

建议实现时保留以下区分：

1. 未来投影可在有证据支持的时点加入已有本金；当前现金展示必须等实际到账回执。
2. T+1 需要赎回提交时点、产品结算规则、预计可用时点；“允许赎回”不等于“已经是现金”。
3. 到期本金保留原归属，不能拿目标定存本金覆盖其他目标或普通义务，除非有明确、有效、符合条件的跨目标授权。
4. 预计利息用于确定性净模拟收益比较；默认不用于硬义务现金保障，以保持未来收入零原则。具体模型需 ADR 明确。
5. 只有提前有损支取才能覆盖的情形保持 `ASK_ONCE`；用户确认以前不把该款计入自动安全计划。
6. 同日到期与同日付款必须有事件先后。未定义时不能假设“同一天”就一定来得及。
7. `UNKNOWN` 回执不能当作到账；当前结果由独立模拟账本及对账确认。
8. 部分赎回、最小粒度、起投、费用、工作日/自然日、节假日与 cutoff 等未明确规则必须补规格，不能乐观猜测。

## 7. 五个手工算例与测试真值

以下是手算结果，基础加减曾独立进行算术核对；没有调用或验证当前业务实现。后续应建立独立 fixture 和断言，不可用待测引擎自己生成 expected。

### 例 A：支付与内部贡献不重复减少保护余量

**适用模式：严格现金保护公式。** 合并现金包含全部本人账户，目标资金仍为现金；生活预算是单次窗口的剩余额度，不是持续滚动底线。各义务具有独立身份，付款已知完成并有账本事实。

初始总现金 10,000，其中应保护：

- 房租 2,000；
- 信用卡 1,000；
- 一次生活窗口剩余预算 1,400；
- 应急 600；
- 既有目标现金 2,000；
- 本期目标最低尚欠 500。

| 检查点 | 合并现金 | 剩余保护总额 | 余量 |
|---|---:|---:|---:|
| 初始 | 10,000 | 7,500 | 2,500 |
| 房租支付 2,000 | 8,000 | 5,500 | 2,500 |
| 再消费生活预算 700 | 7,300 | 4,800 | 2,500 |
| 最低目标贡献 500 内部划转 | 7,300 | 4,800 | 2,500 |

最后目标现金从 2,000 增为 2,500，目标最低尚欠从 500 降为 0，保护总额不变。内部目标划转不减少合并现金。若此步骤余量变成 2,000，就是重复扣了目标最低额。

该例并不意味着所有消费都不影响自主边界：消费来自未预留类别、预算超支、准备金规则变更或新增义务时，余量应随新事实变化。

### 例 B：锁定期限决定目标范围的资产上限

**适用模式：建议的归属＋期限现金流模型；属于完整版多目标资产放置。** 三个目标已充分归属且各自明确允许对应期限的资产配置，所有本金仍为现金。不存在跨目标移动。没有其他本金到账、费用、损失或额外现金底线，用户总额/单次上限和产品容量足够；同日到账先于付款。

| 归属目标 | 确认用款日 | 归属金额 |
|---|---:|---:|
| 目标 A | 第 1 日 | 3,000 |
| 目标 B | 第 20 日 | 4,000 |
| 目标 C | 第 60 日 | 5,000 |

目标现金合计 12,000，**通用 `safe_idle_cents = 0`**。下面是各目标内部合法资产放置额度的合计，不是通用闲钱配置权限：

| 产品本金可用日 | 目标内可配置合计上限 | 理由 |
|---|---:|---|
| T+1，第 1 日 | 12,000 | 按前提到账先于目标 A 同日用款。 |
| 7 日定存，第 7 日 | 9,000 | 目标 A 的 3,000 必须保留现金；仅 B/C 可用。 |
| 30 日定存，第 30 日 | 5,000 | A/B 在到期前用款；仅 C 可用。 |
| 90 日定存，第 90 日 | 0 | 晚于三个目标的用款日。 |

同一产品内各段本金继续保留原目标归属，不可用 A 的额度填 B 的资金。例子对应 F:519、591–599 的目标内放置和期限匹配。若产品同日到账顺序未知，T+1 的 12,000 上限不能沿用，应重新核对。

### 例 C：已有本金到期可覆盖远期义务，有损提前支取不能替代

**适用模式：建议的归属＋日期现金流模型。** 现金与定存本金均属于可承担该义务的同一合法范围，不涉及跨目标资金。没有新增收入、利息计入或其他支出；应急底线恒为 1,000。

初始现金 3,000，已有定存本金 5,000 于第 10 日到期，第 12 日义务 6,000。

```text
第 10 日前：当前可支付现金 3,000，不能显示为 8,000。
第 10 日：确认本金到期后现金 8,000。
第 12 日：支付后现金 8,000 - 6,000 = 2,000。
超过应急底线的余额：2,000 - 1,000 = 1,000。
```

改变到期日为第 20 日，则第 12 日缺口为：

```text
6,000 + 1,000 - 3,000 = 4,000。
```

此时新申购不能自动进行。若第 11 日提前支取全部 5,000 要损失 100，用户确认并实际到账后可能有：

```text
3,000 + (5,000 - 100) - 6,000 = 1,900。
```

虽然确认后的方案可能覆盖底线，确认前仍须 `ASK_ONCE`，不能当作已取得安全现金或已恢复。

严格“今天现金覆盖全部远期义务”的模式会拒绝原始第 10 日到期方案；该差异用于验证未来 ADR 选择，不能混写成同一个测试应有两个结果。

### 例 D：只分配新增资金，月额度是累计额度

**适用范围：目标新增贡献；不是资产放置。** 单目标、当前月份、有效策略；其他保护 3,000 已完整覆盖，无其他冲突。采用“在安全和最低约束满足后接近 target”的目标选择；新增来源账本能识别到账与已分配金额。

原现金 6,000，包含目标已有资金 2,000、其他保护 3,000、旧未归属现金 1,000。目标本月已经贡献 1,000，月范围为 `[1,500, 2,000, 2,500]`。

工资 5,000 真实到账后：

```text
合并现金 = 11,000。
目标分配前可用预算 = 11,000 - 2,000 - 3,000 = 6,000。
新增且尚未归属来源额度 = 5,000。
本期剩余 [min,target,max] = [500, 1,000, 1,500]。
本轮按接近 target 贡献 = 1,000。
```

结果：目标归属增至 3,000，本月累计贡献增至 2,000，合并现金仍为 11,000。重复处理同一工资事件不得新增贡献，结果为 0。

在工资到账前，若没有任何符合资格的新增来源，仅因旧余额有 1,000 可用，不能自行重新把它当新增收入进行自动贡献。若用户另有明确的现存余额分配指令，那属于额外授权情形，不是本例。

最低未完成额为 500 时，它在通用闲钱展示中已经受保护；目标引擎的目标资金预算不能再次把这 500 排除后宣称没有资金完成同一最低额：

```text
贡献前通用余量 = 11,000 - 2,000 - 3,000 - 500 = 5,500。
贡献后通用余量 = 11,000 - 3,000 - 3,000 - 0 = 5,000。
```

另一个必要负例：如果新的安全资金只有 200、最低仍欠 500，不能静默把本期最低改成 200；须冲突/修复流程，除非存在明确适用且有效的授权策略。

### 例 E：90 日与 365 日不同，未来工资不改变当前边界

**适用模式：严格剩余需求公式；不存在资产本金到账。** 初始现金 12,000，应急 1,000，已确认且不续期的首个 14 日生活预算 1,400。另有 12 笔已确认独立义务，每笔 2,000，分别在第 30、60、……、360 日到期；这是显式日期事件，不用未说明的自然月推算规则。投影包含 horizon 当日事件。

```text
90 日：
  三笔义务共 6,000。
  12,000 - 6,000 - 1,400 - 1,000 = 3,600。

365 日：
  十二笔义务共 24,000。
  12,000 - 24,000 - 1,400 - 1,000 = -14,400。
```

完整版必须显示可自主资金 0，同时保留 14,400 的缺口和冲突/风险；不能仅截断为零后显示“安全”。未来预测月薪无论为 0、20,000 或 200,000，执行边界均不改变。

本例生活准备金故意设为不续期的单次窗口，避免把“全年滚动生活预算”的另一个尚未确定问题混进预期值。

启示：完整版黄金链种子须有足够当前资金或合法可用本金匹配全年硬义务。不能缩短投影、删除后续月份或加入未来工资以让演示自动成功。
