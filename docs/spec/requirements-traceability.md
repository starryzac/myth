核对日期：2026-10-03。来源为本项目两份开发计划，保留初版到完整版的全部范围。本表是验收要求清单，不是实现或测试结果。全部任务初始状态为 `PENDING`；只有检查当前代码、命令输出和交付物后，才可更新状态与证据。不得因已有文件、函数名、测试名或空壳命令而判定完成。

## 来源与证据规则

- `M`：[初版开发计划](../../钱途有界_初版开发计划_Codex执行版.md)，对应原始来源 `../开发计划/钱途有界_初版开发计划_Codex执行版.md`；表内数字为计划正文行号。
- `F`：[完整开发计划](../../钱途有界_完整开发计划_Codex执行版.md)，对应原始来源 `../开发计划/钱途有界_完整开发计划_Codex执行版.md`；表内数字为计划正文行号。
- 顺序：MVP-001 至 MVP-504 共 25 项，随后 FULL-001 至 FULL-907 共 67 项，总计 92 项。不得跨 Epic 并行修改核心模型；完整版以初版为前置，见 F:11、1782–1789。
- 每项共同完成证据：实际实现文件、必要测试与真实输出、必要文档、迁移或示例、`docs/progress/<task_id>.md`。进度记录包含完成内容、改动文件、设计选择、实际运行命令、测试结果、限制和下一项前置条件（M:43–56）。完整版还要求必要 ADR、失败测试先于实现、OpenAPI/类型/迁移/文档更新、实际 `make check` 成功（F:89–97）。
- 下表“应提供的验收证据”均为待取得要求，不代表已经存在。完成时填写可追溯路径、运行 ID、时间与结果；人工审核必须注明审核人、时间、结论及未覆盖范围。外部用户研究不得以合成记录代替。
- 跨任务的质量门、具体命令、算法不变量、数据与材料要求见 [全局验收清单](acceptance-checklist.md)。

2026-10-04 用户更新验证节奏：全量仅在初版完成、完整版完成两个验收节点运行，失败修复后可在同一节点重跑。上方原计划中的逐任务 `make check` 要求，其执行频率按仓库 AGENTS.md 1.4 节覆盖；任务仍须有实际模块和直接相关测试，资金守恒、防重复扣款、UNKNOWN 恢复、迁移须有对应集成，前端须有类型和页面验证。历史全量证据保留，不重复生成逐任务全量。

## 完成状态变更原则

1. 先验证要求，再写状态；`PENDING` 不因建立本表而变更。
2. 不能把实现完成、单元测试完成、真实 PostgreSQL 集成、真实浏览器 E2E、断网演示、研究开展、人工审查混为一项。
3. 若依赖不可用，记录精确缺失能力和已取得证据，继续不依赖该项的工作，不得制造替代结果。
4. 任何冻结案例违反硬约束，停止效果结论；基线不支持研究优势时降低主张，记录计划的停止或降级条件（F:1693–1700）。
