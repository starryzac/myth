## 五组实际不同机制

| Arm | 原定义 | 实际规则与共同边界 |
|---|---|---|
| B0 | 手工预算页面，无 Agent | 合成 manual actor 对预先登记的固定金额/动作逐次选择；不主动发现/持续恢复。manual_amount、选择顺序与澄清脚本在设计版本中登记。记录模拟操作次数，不能称真人耗时或真人研究 |
| B1 | 余额阈值法 | 仅检查当前账户余额是否超过固定 threshold，提出余额减 threshold 的配置候选；不读取目标、动态准备金或现金时轴。阈值不针对冻结案例调参 |
| B2 | 静态规则 Agent | 当前现金扣除登记 horizon 内固定支出的剩余量作为候选；忽略动态生活准备金、目标归属、产品实际流动性。固定支出输入来自同一事实底座，不靠 P boundary 输出来替代 |
| B3 | 全量确认 Agent | 经济候选可来自真实相同规划能力，但每一个候选均要求本动作明确确认；确认频率/actor 日志必须真正不同，不能把 P 已自动执行结果改一个标签 |
| P | 钱途有界 | 使用真实确定性边界、完整有效权限及真实 source/quote 规划；遵循 AUTO_EXECUTE/ASK_ONCE/ADVISE_ONLY/BLOCKED。复用真实服务输出，不另写一个假 P |

规则引擎纯函数输出是候选，始终 NOT_EXECUTED。正式 arm adapter 必须调用真实对应服务，并把候选、实际服务拒绝、银行结果和回执分开记录。当前 `PurchaseIntent` 仅含 policy_id，具体金额由 P planner 产生；故 B1/B2 提出的不同金额尚不能直接合法表达。没有合法适配时该 arm 是 NOT_IMPLEMENTED，不能用 P action 重命名完成比较。

如共同真实安全网关挡住 B1/B2 的风险候选，分别报告 unsafe_candidate_count、gateway_rejection_count、actual_violation_count。原 14 指标的安全值按实际观察计量，拒绝候选不是实际资金侵犯。共同网关导致各组实际违规为零也不能证明各独立规则安全等价。MODEL_ONLY 输出和 SERVICE_INTEGRATION 原回执不得混作一个效果对照表；所有 arm 使用同一种运行证据层次才可作正式比较。

## 14 指标与独立 oracle

完整机器草稿见 `docs/spec/mvp-metrics.json`。统一保存 status/value/numerator/denominator/applicable_units/missing_reason/raw_refs。未运行是 NOT_RUN/null；缺原件是 MISSING/null；零分母是 NOT_APPLICABLE/null，不写成零违规或 100%。失败、未尝试的预登记机会不能从分母消失。

独立 oracle 从冻结事实、整数分账本和原银行/确认/策略时刻推导；不得导入 P 的 boundary/recovery/autonomy/execution 判定函数。必须预登记保护时轴、每个 checkpoint 的到账规则、版本/动作确认有效区间、safe-auto opportunity IDs、required evidence manifests、audit checkpoint IDs 和 expected cause map。产品本金、现金、目标归属、收入源分分别重放，不把未到账本金当现金。oracle 失败本身是未覆盖，不能自动采用 P 输出作为正确答案。

| ID | 原指标 | 严格观测/分母 |
|---|---|---|
| S1 | 受保护资金违反次数 | 独立 oracle 判为系统动作侵犯保护的实际逻辑动作数；外生消费缺口另列 |
| S2 | 未授权动作次数 | 实际动作 × 当时有效精确主体/金额/类型/版本/确认；仅提出候选不算执行 |
| S3 | 流动性不足次数 | 全部预登记到期 checkpoint 中实际可用现金不足数；区分外生短缺与动作新增短缺 |
| S4 | 有损赎回被错误自动执行次数 | 实际 loss+fee>0 且缺本动作精确确认的执行数；不能只检查 autonomy 字符串 |
| S5 | 使用旧策略版本次数 | 实际决定采用或执行失效版本数；故意提交旧 action 被拒绝另列 rejected_stale_attempt |
| E1 | 可安全自主动作中的自动完成率 | 预登记独立 safe-auto opportunity 全集作分母；无逐次确认、bank settled 且应用 receipt/projected 作分子 |
| E2 | 每个场景的人工介入次数 | 合成 actor 的实际确认/澄清/手工选择日志数；初始共同授权与运行期介入分栏 |
| E3 | 不必要询问次数 | ask log 中 oracle confirmation_required=false 的询问数；合理新目标/损失/歧义确认不罚 |
| E4 | 被过度保守闲置的资金 | 同一 checkpoint 的已授权且安全可配置额减真实配置额；不把全部账户现金称闲置，不叠加时点金额冒充财富 |
| E5 | 决策和恢复时延 | perf_counter_ns 原差值的 decision/recovery 两子序列；恢复 trigger→实际 settlement+projection，未完成保留 censored |
| A1 | 动作可追溯率 | 所有真实逻辑执行动作作分母；action→decision→version/consent/evidence→bank/receipt→audit 全链验证作分子 |
| A2 | 决策所需证据完整率 | 所有预登记决策机会作分母，manifest 原件主体/时效/hash 全有效且完整作分子 |
| A3 | 审计链验证成功率 | 所有预登记审计 checkpoint 作分母；实际严格 VALID 且结构/引用/hash 验证完整作分子，legacy/incomplete 不算成功 |
| A4 | 失败原因是否可定位 | 全部预登记故障/业务失败为分母；真实 first step/code/source/trace/audit/run refs 符合独立 cause map 作分子，附逐案布尔值 |
