## 第2页　余额有界，用途才清楚

> 青年资金场景来自产品问题定义，尚无真人发生频次

### 同一余额，不同约束

工资到账后，余额可能同时承担房租、账单、生活准备金、应急和长期目标。把它们合并为一个可投资数字，会丢失截止时间、已确认用途和资产流动性。系统要回答的是某笔动作能否在每个保护时点维持现金覆盖。

### 今日事实与未来意图

已到账收入有原流水与来源；下个月工资只是未来展示。产品本金可能尚未可用，目标归属也不能被一般资金缺口任意借走。缺事实、缺条款或缺授权时显示UNKNOWN，不能补零。

### 服务范围

普通消费只作为用户自己的账户事实，不评价其生活选择，不推荐商户。单银行体系闭环是设计范围；痛点强度、使用频率、理解效果与接受程度仍需成年人模拟研究，当前没有比例或用户规模数据。

## 第3页　把安排能力与执行权限分开

> 比较的是机制，未做市场份额或效果优劣结论

### 手工预算与阈值

手工预算依赖逐次选择；余额阈值只观察一个时点。它们可作为实验基线，但不能凭定义认定其不安全，也不能把共同安全网关拒绝的候选算成真实资金违规。

### 静态规则与全量确认

静态规则忽略动态保护、目标归属或到账时刻时，候选可能偏离真实约束；全量确认则用每次明确确认换取保守执行。钱途有界拟检验在确切已授权动作内减少重复介入的可能性，现无对照效果数值。

### 确定性产品边界

金额、状态、约束和执行由规则与引擎计算。模型候选不能新增用户角色、银行事实、额度、成功结果或授权。五组实验必须调用实际不同机制，不能把P的回执改名为B0—B3。

| 机制 | 候选来源 | 当前比较证据 |
| --- | --- | --- |
| B0 / B1 | 手工选择 / 余额阈值 | 未完成正式执行 |
| B2 / B3 | 静态规则 / 全量确认 | 未完成正式执行 |
| P | 真实边界与原权限 | 局部链路证据，非优势证明 |

## 第4页　事实 → 策略 → 边界 → 动作 → 回执

> 一笔动作可回到当时的原来源和原确认

### 不同来源，不同职责

账户、流水、账单与产品条款构成有时效的事实；USER_DECLARED表示用户意图；复核原配置哈希后才能形成确认的不可变版本。READY_FOR_REVIEW不是ACTIVE，HTTP200也不是银行结算。

### 提交前重新核验

规划从当前事实和版本产生候选；prepare保存具体经济效果。需要单次确认时绑定同一effect hash。实际执行和首次银行受理重新核验当前权限、保护和原引用，避免使用读取时的旧状态。

### 恢复仍是同一笔

应用与模拟银行状态分开。响应丢失保留原action/key和UNKNOWN；只能查询、协调或人工核对原件，不能换键新增动作来绕过未知结果。原银行已结算而应用未投影并不意味着现金没有变化。

| 层 | 回答的问题 |
| --- | --- |
| 事实 / 策略 | 发生了什么 / 用户确认什么 |
| 边界 / 动作 | 当前允许什么 / 具体经济效果是什么 |
| 银行 / 回执 | 实际结算什么 / 原投影是否一致 |

## 第5页　首次引导与三条黄金链

> 八步是草稿与复核位置，不是八次自动授权

### 首次引导

账户摘要与交易来源、房租账单候选、持续时间与优先级、生活准备金、应急、未来目标、资产及恢复授权、最后权力边界复核。只在用户主动点击时发现或声明候选；退出可恢复草稿和未决原请求。明确确认仍通过实际策略或目标入口。

### 三条真实业务内容

A：工资到账，先保护再目标分配与允许的申购。B：自然语言目标产生候选，用户修改、首次确认ACTIVE，后续新增收入再分配。C：消费收缩后按原授权无损恢复，出现定存损失则展示原报价并明确询问。

### 当前演示缺口

历史三轮原生录屏可作为历史素材，不能替代最终当前源的完整三链。当前版四分钟主演示、备用离线三链、B链完整画面与真人内容审阅未全部取得；本包交付的是240秒计划脚本，不声称录制或实测时长完成。

## 第6页　五集合交集定义自主边界

> 安全金额不等于用户自动授权额度

### 包络定义

AutonomyEnvelope = FinanciallySafeSet ∩ UserAuthorizedSet ∩ LiquidityCompatibleSet ∩ EvidenceSufficientSet ∩ SupportedActionSet。只看余额、单个财务安全上限或旧确认，均不足以证明AUTO。任何集合未知或不满足，都保留具体拒因。

### 分级结果

AUTO_EXECUTE只用于当前满足原授权与约束的动作；ASK_ONCE要求确切经济效果的单次确认；ADVISE_ONLY只建议；BLOCKED禁止动作。标签来自确定性服务，不由模型置信度或前端按钮产生。

### 资金时间轴

完整年度保护使用初始日加365未来日期，每日期三个阶段，共1098阶段点。付款前、付款后和本金到账后分开，不能把1098误写成天数。未来收入计入今日自主资金为0，条件回款不变成实际现金。

| 集合 | 不足时的处理 |
| --- | --- |
| 财务 / 流动性 | 保护缺口、可用时刻不符 → 拒绝/未知 |
| 授权 / 证据 | 缺版本、原确认或来源 → 不自动执行 |
| 支持动作 | 未实现的动作族 → 明示未覆盖 |

## 第7页　策略会变，归属不能偷偷变

> 当前版本、历史版本与变更影响分别展示

### 不可变生命周期

创建、修改、暂停、撤销、恢复采用原配置、版本与顺序命令。旧回执证明历史动作，不是当前资金权限。原键lookup返回确切原body/hash；NOT_FOUND非终局，客户端保存原请求并锁住新写。

### 目标与最小修复

Full目标模型增加属性、底线和节奏，需双hash明确确认；联合规划与冲突预览显示原goal分母和候选，而不是宣称全局多期最优。跨目标默认关闭；专用回拨授权只声明scope，实际回拨要再核原三腿效果与具体确认。

### 修改影响

当前资金差量预览仅对已支持的未来DatedExpense/PeriodicTransfer重新计算保守曲线；今日、逾期和当前月义务保持原含义。其他模板及未来目标分配保持UNKNOWN。预览没有写事实、资金或当前动作。

## 第8页　只问会改变动作的问题

> 有限世界是完整枚举范围内的计算，不是安全概率

### 不确定性与反事实

有限变量形成最多128个世界；每世界调用原引擎，保留当前来源、权限和拒因。旧动作的单次确认不会自动授予反事实动作。缺来源的世界记UNKNOWN并留在分母，不能剪掉后宣布稳定。

### 一次一问

服务持久化session/revision、原问题与答案，按当前动作语义分歧选minimax问题。回答只筛选世界，随后重算，不是金融确认。来源变更或过期使旧答案失效；CLOSED不重新生产问题。

### 通知不是已读

原Question提交后独立观察通知；观察、投递、Inbox claim、ACK、回答和资金确认是不同动作。当前观察proof与旧immutable payload分开展示，已领取/ACK或旧终态不能借refresh复活。通知本身不授予银行权限。

| 动作 | 它不代表什么 |
| --- | --- |
| 回答 | 不代表同意执行资金 |
| observe / deliver | 不代表真人已见 / 已答 |
| ACK | 不代表答案或具体经济授权 |

## 第9页　产品期限必须匹配钱的用途

> 规划容量、可购买性与真实执行分别证明

### 产品与本金可用

目录版本和条款先验真，再按期限、到账、风险、锁定、金额和用户范围筛选。活期、T0、T1与固定产品是模拟类型，不代表工行实际在售产品。期限分桶与续期规划只依据当前已知条款。

### 整组执行

原组合prepare固定full/MVP/goal版本、整组hash及确认。execute-next固定expected batch/action，一次一批；原批重放不推进下一批，UNKNOWN后批停止。读取保留原consent、银行key与回执，不自动回滚或替键。

### 恢复与到期

无损资金恢复受scope和当前保护约束；有损支取必须展示原报价及单次确认。到期已实收后重新读取当前事实/策略/目录，原成熟回执不是新授权。当前Full恢复、动态目标等新路径真实集中验收仍待，不能把候选容量当权限。

## 第10页　解释可回原件，异常可留未知

> 对账吻合不等于经济效果独立证明

### 决策和审计

DecisionTrace关联输入、策略/产品/算法版本、约束、原行动及原receipt。typed审计核原canonical/event/reference/checkpoint，不用通用自制hash替代原协议。缺现代审计的旧历史保持LEGACY_UNAUDITED，不回填可信起点。

### 三账口径

只读对账比较应用现金、独立模拟银行和Goal归属；差额为应用减银行。缺原件的bank数值或差额保留null，不能填0。MATCHED表示本快照账目符合当前核验范围，既不是每个准备动作都执行，也不是现实经济验真。

### 身份和界面

服务器固定本地USER的签名HttpOnly会话只模拟身份，不是真人KYC或金融确认。金融每次请求独立验真；跨页pending、原键恢复和存储错误门避免产生第二动作。手机与键盘样式已增量实现，实际可用性/无障碍审阅仍待。
