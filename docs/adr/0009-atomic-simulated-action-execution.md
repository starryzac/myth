# ADR 0009：可确认、可重放的模拟资金执行

设计状态：ACCEPTED for MVP-301（2026-10-04）。实现状态：VERIFIED，完整check 20261004T015335Z-2add56ab通过，见MVP-301进度及原始证据。前置MVP-205已提交0950db2。依据[初版计划](../../../开发计划/钱途有界_初版开发计划_Codex执行版.md)8.4、8.5与MVP-301，以及[完整计划](../../../开发计划/钱途有界_完整开发计划_Codex执行版.md)12.1—12.4；[只读预审](../progress/MVP-301-preflight.md)保留设计依据。下述说明记录当前实现合同，不替代最终验收。

## 范围

实现内部划转、周期义务支付、目标储备、资产申购和赎回的真实模拟经济效果；补全205明确留待本项的有损报价确认后执行。提供准备、execute、confirm、只读动作/receipt闭环。全部仅合成模拟，不接真实银行。302完整等级矩阵、303完整决策追溯、304审计链和FULL消息可靠性仍按顺序验收。

内部划转必须由用户给出具体源/目标/金额，准备后明确确认；不能由系统猜测新转账意图。目标、申购和无损恢复仅可从已确认最新策略与服务器事实生成金额、对象和来源。客户端不得指定user、服务端时钟、级别、授权结果或任意银行分录。

## 准备、确认和执行

准备持久化不可变经济载荷、原策略版本、来源引用、稳定effect_hash、有效窗口和预期后态，不产生资金效果。相同用户/准备键和相同意图返回原动作；同键不同意图409，不以新时钟自动替换历史动作。

明确确认绑定动作、用户、effect_hash及显示的本金/费用/损失/净到账、源目标、归属、产品原条款、收款人、来源位置、到账上界和期限。accepted必须严格为true。它只授权这一笔后果，不创建持续资产权限；每次查询变化的as_of不进入经济确认hash。过期、变价、旧版本、资金变化或不能达到已显示到账上界时必须重新重验，不能静默更换载荷。

不可变银行命令保存在ActionPlan.request.execution，包含effect与effect_hash，并与独立BankOperation的请求逐项核对。申购必须显式提供return_account_id与purchase_exit，二者均进入经济确认hash。return_account_id必须是实际出资账户之一；目标申购必须返还同一目标账户。不得从cash_uses的排列顺序推导返本账户，否则排序归一后可能出现hash不变而资金去向改变。

执行在锁内重验当前版本、对象、事实完整性、现金/收入片段/管理额度/仓位占用及全部273点后态。仅financial_only结果不足以授权。新提交与银行受理均核验权限；银行已有效受理后的撤销不抹掉已发生效果，对账仍须完成。

## 五类后态

内部划转现金一减一增，目标归属保持；不得将已归属目标现金转为一般资金。原收入origin及发生时间不变，部分转移只拆分当前位置；接收流水为INTERNAL_TRANSFER。

周期支付绑定bill_id或policy_id+自然月，并与策略版本分离。通常只在已到期/逾期时执行，prepare_days_before不代表提前扣款许可。exact使用当前明确未付额，bill_balance使用原真实账单；range的max仅是保护上界，必须有明确本期final_total，且位于授权范围，才可支付/结清。付款现金减p与同笔paid加p同时投影，不能删除以后月份的义务；真实账单不再重复生成普通周期结清。已知合成收款身份必须独立于任意policy字符串核对，新收款人不能自动执行。

目标储备复用203按当前版本计算的新增来源和月范围，消费原片段；总现金不变，目标现金/allocated/月贡献加p。同账户归属变化不制造虚假现金转账。

申购复用204当前可行性，普通投资基线必须READY；现金减p、银行新仓本金加p，目标申购仅现金转同目标本金，allocated/月贡献不变。银行先记录真实新仓经济效果，应用随后建仓，不先造HELD本金占位。产品具体版本与条款固定，执行时重新验证锁定/退出方案，未来收益不计安全现金。

多账户出资时，每一笔真实银行现金扣款分别投影为该账户、该金额的ASSET_PURCHASE流水，不为任意一个账户伪造全额扣款。新仓证明使用execution-purchase-v1，保存完整且唯一的purchase_transaction_ids、兼容单笔读取的purchase_transaction_id，以及显式return_account_id；所有出资流水合计必须等于新仓本金，并与原命令和独立银行分录对应。

purchase_exit固定原退出种类、请求时间（如有）和本金可用上界。PLANNED_REDEMPTION仍是未提交的主动赎回计划：新仓证明标记UNSUBMITTED_PLAN，实际principal_available_at保持为空，不生成银行已受理或本金将到账的事实。执行还必须以该实际新仓状态重验全部边界点为READY，不能依赖尚未提交的主动赎回支撑未来硬性保护。固定到期则按真实银行settled_at加原条款期限及结算等待重算，须不晚于原purchase_exit和latest_arrival_at的上界；CONTRACTUAL_MATURITY只表示合同未来返本，未到账本金仍不是当前现金。未来主动退出的调度不在本项实现范围内。

无损恢复保持205原门。明确有损恢复另设财务门：对全部对应点after >= min(before, 0)，且至少改善一个原负点；可消耗已确认成本所需的正缓冲，但不能制造新缺口或恶化原缺口。净额内扣P=net+fee+loss；现金加net、原仓结清、旧返本事件替换。目标仓allocated减实际成本，历史月贡献不回写，不能两次扣费。银行到账及应用对账前不称风险已恢复。

已授权硬义务付款可以在既有缺口下履约，但对应273点不得恶化负余量或制造新的缺口；只释放同笔实付/已明确最终金额对应的保护。该许可不用于投资或任意转账，不删除其他保护。

## 银行、预留与幂等

沿用应用提交请求→独立银行提交→应用新事务投影的三段真实commit。0004增加统一BankOperation和ActionResourceReservation；保留205旧Redemption及分录原ID/金额，通过原ID回填统一operation，新旧路径共享同仓关闭保护。现金、本金、收款、费用损失、归属和来源位置分录各自守恒，不把备查账加进现金总额。

第一阶段在用户锁内重验并持久化SUBMITTED、资源与收入预留后提交；第二阶段由独立模拟银行提交经济效果；第三阶段在新的应用事务中按原operation投影余额、交易、账单/周期实付、目标归属、仓位、收入、预留终态和回执。银行ACCEPTED尚未到账时不投影到账现金或成功回执，继续保留占用；只读查询不触发结算。第三阶段失败不能回滚或抹除第二阶段已经提交的银行效果。

银行可在应用AssetPosition创建前建立新仓账；仅解除银行对应用仓位投影的耦合，不削弱应用关系与用户隔离。可信开户来自明确模拟指令，正常执行不得复制可编辑应用余额为真值。

同键同载荷始终返回原尝试。同业务身份在已受理、UNKNOWN或成功时持续占用，换键/修改策略不产生第二次付款或第二次赎回。银行响应丢失、未知异常或应用投影失败均保留原动作和预留，进入UNKNOWN后查询原操作并补同一投影。只有确定的银行拒绝与独立无效果检查共同成立才释放：当前本地适配器在确定拒绝路径中加锁核验不存在operation和经济分录，或存在与原命令/hash一致的REJECTED且无经济分录。普通超时、任意FAILED标签或单独一次“查不到”均不是释放依据；已有ACCEPTED/SETTLED不得借拒绝路径释放。批次一项失败不得阻止其他已发生效果对账。

延迟返本区分经济时刻和观察时刻：原已受理请求的`settled_at`与分录`occurred_at`保持承诺`available_at`，晚查询的`created_at`记录实际写入时间。两种银行入口共用顺序门；有更早已到期受理操作时须先处理原操作，再接新写入，不允许倒序插入经济历史。当前无后台调度器，GET仍然只读。

正常新建目标只为刚创建的零归属建立GOAL_CASH/GOAL_PRINCIPAL零锚点，并先核验已有银行事实；重复创建不会从既有正余额投影补造银行锚。已完成动作读取与重放共用只读历史回执核验，绑定独立操作、完整且唯一的分录、金额和结算/观察时间。核验不重新授予权限，也不因缺回执自动重新执行。

## 收入来源兼容

保留v1读取，新增原始origin与当前location/fragment表示。origin原金额、时间、银行证据/hash不变，fragment可跨账户拆分和合并，各位置spent+assigned+reserved+available守恒。旧v1非零reserved作为legacy占用保留，不能猜测绑定新动作或清零。

目标执行对原片段原子预留/消费；划转、返本、退款或旧余额不产生新收入资格。新的银行事实与余额/归属/月贡献/来源/完整曝光证明在同一投影事务刷新；不能只搬as_of却丢失消费或伪造新增历史覆盖。固定完整历史不会随时钟自动延长。

准备时将收入证明id/hash固定在request.income_evidence，确认或执行不能静默改写该引用。时钟推进导致证明换代时，仅接受可验证的supersedes链：同用户、可信银行来源、内容hash和状态有效，且链上除as_of外的完整经济载荷完全相同，包括origin、location、available、spent、assigned及全部reserved。另一笔预留、消费或来源变化必须重新准备；纯时间携带不得重置旧占用。银行受理前重验只可回加本动作自己的有效预留，不能回加其他动作或legacy预留。

缺失完整收入账本时不从余额猜新增资格。目标储备必须有完整来源；其他动作可在不需要新增收入资格且独立现金事实完整时执行，但不得据此新建INCOME。若账本已存在，必须同步保存或消费原来源，冲突或无效账本不得当作缺失跳过。模拟银行来源位置开户仅来自明确可信导入，正常执行不能把应用可编辑账本复制成独立银行真值。
