# ADR 0003：明确确认、追加版本与保守动作失效

日期：2026-10-04（Asia/Shanghai）。状态：ACCEPTED，29 项生命周期与完整 make check 已通过，见 MVP-103 进度记录。

## 背景

MVP-103 要求策略确认、修改、暂停、到期、撤销，修改后旧动作失效并可查询历史。金融动作仍为后续任务，生命周期实现不能把未知执行结果当成失败重付，也不能仅靠可变 ACTIVE 字段授予权限。

## 决策

1. 配置先通过纯确定性 DSL 校验、补齐缺省值，再生成审阅摘要；明确 `accepted=true` 且摘要一致才产生版本和用户确认证据。配置内账户、目标、资产策略引用另查真实所有权和类型。
2. PolicyVersion 仅追加。0002 数据库触发器拒绝 UPDATE；受控演示 DELETE 仍可用。配置哈希与前配置哈希只是配置追溯，不包装成整条版本链的密码学防篡改证明。
3. 证据必须同用户、存在、有效、非未来且内容摘要正确；确认内容与不可变版本记录完整绑定。持续授权还必须是最新版本、已确认并处于有效时间区间。
4. 所有写操作在调用方事务内使用 savepoint。按用户→策略/候选→动作锁定；相同预期版本的并发修改仅一个成功。实现牺牲同用户写吞吐量以降低原型阶段的并发复杂性。
5. 未来起点保持 CONFIRMED；新版本立即替代旧授权，不用旧版本填补未来生效空窗。暂停中修改仍暂停；已撤销或到期的策略不能借修改复活。MVP 没有 resume。
6. 日期按用户本地日界解释，终日转次日零点排他；明确确认时间之前无授权。刷新保存实际状态，授权读路径独立计算时间，避免依赖定时任务是否已运行。
7. 动作依赖遍历全部旧版本、决策快照与决策约束。仅无回执的 PLANNED/AUTHORIZED 可以 INVALIDATED。提交中、结果未知、未提交却已有回执、失败但最新回执未知/已执行的记录保持原身份与状态并返回待对账清单。生命周期服务不解决或重新提交这些动作。
8. 幂等重放返回首次命令的历史回执。响应 schema 描述明确其历史含义；用户界面必须再 GET 当前状态，执行服务必须重新核验持续授权。
9. 已有目标只更新配置投影，不移动账户现金、既有归属和持仓，不改绑持仓的历史策略版本。新目标的建立、分配留给对应后续任务。

## 验证与限制

先保存真实失败，再通过 PostgreSQL 的 29 个生命周期用例；加上迁移与演示重置兼容性共 49 项必要回归通过。真实并发、真实插入故障、不可变触发器、证据篡改和在途异常组合都有测试证据。

当前不实现 FULL outbox/inbox、对账、资金恢复或审计只追加签名；不承诺阻挡管理员删除/禁用数据库保护。`is_version_authorized()` 是资格读取，不是脱离事务后永久有效的执行许可。下一阶段应沿相容锁序，在资金执行事务中联合重验策略、资金边界、资产可用性与幂等状态。
