# ADR 0008：独立模拟账本支持的安全恢复

状态：ACCEPTED / VERIFIED for MVP-205（2026-10-04）。本项完整check `20261003T233659Z-bec8c501`通过850后端/4前端/1Edge，129源码摘要一致；详见[验收记录](../progress/MVP-205.md)。依据初版8.5、MVP-205和完整版12.3；冻结SEM-08，不放宽204普通投资必须READY的门槛。

## 范围和完成条件

本项实现整仓、零费、无本金损失的T0/T1恢复专用闭环，以及已到期合同本金的一次结算/对账。一般现金已包含在快照中，不能再额外增加一次。原目标本金回款仍属于原目标，不能填一般资金缺口；目标内部回款可正确对账，但不得跨目标挪用。

205必须有真实模拟银行经济效果、应用对账、ActionReceipt、边界重算和可查询本地通知。只读计划、请求受理或SETTLED标签本身不算完成。业务页面、全动作执行框架、完整自主等级矩阵和审计哈希链仍由301/302/303/304及401–404分别验收。

有费用或损失的提前支取生成ASK_ONCE提案，绑定user、position、原产品版本/条款hash、返还账户/归属、本金、费用、损失、净到账、时点、当前策略与事实hash、有效期及不可变提案hash；不得自动执行，不暴露假成功的确认入口。确认后的有损执行必须保留为301待办。此阶段划分依据M:116–123、548、752–753、817、1034及F:706，不从完整目标中删除该闭环。

## 恢复许可和时间

来源完整后计算真实基线。每个候选的所有273个对应财务检查点不得比当前累计预计方案更差，且至少一个原负余量点改善，才具有恢复财务价值。允许仍有缺口的部分改善；不能要求全窗最小余量立刻提高，因为T1之前的负点还在。已没有可改善负点就停止，不能为增加正余量多赎回。

按T0、T1、已到期资产及稳定持仓UUID顺序尝试，不进行收益搜索或多产品优化。每次仅整仓，不假设分级部分赎回规则，也不拆同一仓规避单次上限。恢复前后的义务、生活、应急及目标保护口径不变。

T0预计效果使用明确“到账后的反事实快照”：现金加本金、该持仓结清，目标本金与现金归属同步转换，再重算202边界；保留真实baseline作为当前事实。禁止通过as_of+1微秒绕过202对历史未结清本金的检查。T1以明确未来到款时点投影，仍按当日先付款、后本金可用；在途不增加真实账户现金。返本必须替换同一持仓原有未来到期事件，禁止重复加入本金。

actual_boundary、projected_boundary/轨迹、未覆盖检查点、预计持续安全起点和执行状态分别输出。只有独立银行posting已对账进应用且最新实际边界无缺口，才能标记RECOVERED；T1在途、UNKNOWN、部分到账及来不及时继续明确未解决风险。不能用预测到账或未来收益填当前缺口。

## 授权与条款

每次新的自主请求核验原购买授权、当前最新确认授权、准确持仓/原产品版本、全部归属、有效期、无损恢复开关、产品自动赎回许可、锁定/赎回约束及单次上限。用原授权与当前授权共同约束整仓请求；剩余购买管理额度不作为减仓上限。当前暂停、撤销、过期、旧版本均不能授权新请求。

已经完整证实的人工持仓而无原恢复授权为ADVISE_ONLY；缺关键事实且会改变动作时补证/ASK_ONCE，不能借提问凭空形成授权。现有种子三笔人工v1持仓不能自动套用v2条款。正例须有真实确认链和可信原购买/持仓证据。报价须绑定原position和product版本，不把类别名称当作无损保证。

自然合同到期是原经济事件的结算，不是新申购或第二笔本金。若当前投影已过可用时间而尚未对账，应先按独立银行事实完成对账，保留202原守卫。已经被银行有效受理的请求在授权后来到期/撤销时仍须如实查询和结算；不能抹去已发生效果或换键重提。

## 独立模拟银行和事务

增加最小银行请求和posting表：请求绑定不可变经济载荷、原动作及整仓身份，同持仓、同动作和用户内幂等键各自唯一。posting独立记录CASH/ POSITION账本键、序号、前后余额、带符号金额、操作及前条引用；本金减少和现金增加两腿均唯一且守恒。OPENING来自一次性可信模拟种子锚点，不能在结算时复制应用余额当作银行真值。

三段事务明确分离：应用请求先持久化；银行独立事务受理/结算；应用新事务消费银行posting并更新投影/回执。银行不能引用尚未提交的Action FK，避免隐藏阻塞。银行提交后丢响应或应用投影失败时，重试只查同一请求、补同一投影，不产生第二次经济效果。可用205专用Engine驱动服务管理边界，不受普通HTTP单个Session自动提交约束。

同用户/持仓/银行账本必要锁及唯一性阻止同键重放、同键改载荷和不同键争同仓。T1受理仅锁定本金并标记REDEEMING，现金及管理占用不释放；到款后从银行两腿posting派生唯一PRINCIPAL_RETURN流水及ActionReceipt，再核余额/持仓。回执引用银行posting，不能拿应用动作日志自证成功。

## 来源适配与既有模块

扩展完整曝光协议以支持已受理/已结清赎回，保留v1解释与原购买链；银行请求/posting集合纳入完整性校验。不能凭REDEEMED标签释放占用。余额、持仓、目标归属/贡献、已有收入lot及曝光证明在一致时点更新；已归属目标和203新增收入资格不因本金返还增加。不可为更新证明而重置旧消费、在途预留或月累计。

已结清原持仓不再按原可用时间重复加现金。应用余额或持仓被修改而与独立银行事实不符时关闭精确规划并要求对账。只支持本项赎回/到期适配，不提前实现301支付、划转、申购的通用dispatcher。

## 独立真值与验收

- 现金70000、保护100000、T0整仓50000：实际回款后现金120000/余量20000；请求前仍缺30000。禁止默认仅赎30000。
- 同一缺口T1整仓30000：今日及明日付款前后仍缺30000，明日本金到账阶段预计余量才0；原全窗最小值仍为-30000。
- T0整仓10000与T1整仓20000：首次到账仍缺20000，第二笔实际到账且对账后才恢复。
- 现金70000中目标现金20000，其他保护80000，目标本金30000回原目标：现金100000、目标现金保护50000、总保护130000，通用缺口仍30000；allocated和月贡献不变。
- 原整仓30000排day5返本，提前全部返还后day5不得再加本金；同键/不同键重放也不能多出一次。
- 本金30000、费用100、损失0：净到账29900、余缺100，只能ASK_ONCE；报价变化/过期不得沿用旧提案。

每组先记录真实失败再实现。必须验证真正T0回款/回执/本地通知、T1受理与到账、部分恢复、来不及、人工无授权、旧/撤销权限、产品旧版本、费用/损失不自动执行、同仓并发、银行提交丢响应、应用补投影、篡改应用余额被发现、目标归属及收入资格。完整make check、迁移、重复种子、源码摘要和任务文档通过后才能进入301。
