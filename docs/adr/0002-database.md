# ADR 0002：MVP PostgreSQL 模型与迁移边界

日期：2026-10-04（Asia/Shanghai）。状态：ACCEPTED，真实 PostgreSQL 往返及整体 make check 通过，见 MVP-101 进度记录。

## 背景

初版计划第 7 节列出 16 张核心表，要求整数分与 UTC 时间，但未逐列规定字段。MVP-101 要求全新数据库升级、回滚后再升级一致。后续策略版本、动作幂等和审计追踪依赖稳定的数据关系。

## 决策

1. 保持模块化单体、PostgreSQL 16 和 SQLAlchemy 2。测试使用同一个 PostgreSQL 实现，不以 SQLite 替代。
2. `MoneyCents` 映射 BIGINT，应用绑定拒绝非整数和布尔值；数据库 CHECK 按字段规定金额范围。收益率为整数基点，避免浮点金额。
3. `UTCDateTime` 映射 TIMESTAMPTZ，拒绝 naive datetime，连接时区与返回值统一 UTC；日历日期保留 DATE。
4. UUID 主键，租户所有权使用 `(id,user_id)` 唯一键和复合外键，金融与审计引用使用 RESTRICT。不把引用完整性冒充身份认证或 RLS。
5. 业务主键各自显式唯一：银行来源、策略版本、用户内决策/动作幂等键、动作尝试序号、审计序号和哈希。数据库去重不替代未来事务执行协议。
6. 可演进配置、计算过程、快照和回执载荷使用 JSONB；策略配置至少限制为对象。多证据 ID 数组是快照，不是外键集合，领域层以后验证其语义和所有权。
7. 为完整版本保留产品版本、生效区间、事实观察/有效时间、确认记录、精确策略版本、UNKNOWN 状态和事件关联字段；不提前实现相应领域服务。
8. 固定初始 Alembic DDL；历史迁移不依赖随应用变动的 ORM 元数据。自动生成只是写迁移的工具，迁移经实际 PostgreSQL 往返和元数据差异检查后接受。
9. 降级仅允许临时测试库 `bf_test_<32 hex>`，禁止普通库和离线降级。测试通过随机名称隔离，清理只针对本次确实创建的数据库。演示库重置留给受控种子任务。
10. 账户余额、未赎回持仓和目标归属分别存储；账户余额仅表示现金，目标归属不能额外加到总资产。现金管理与定存账户类型保留，产品本金由持仓记录。

## 验证与后果

测试先因缺失数据库模块失败，再通过真实 PostgreSQL 16 的结构往返、元数据对比和负向约束测试。`docs/architecture/database.md` 列出具体 16 表与验收边界，原始日志位于 `docs/progress/evidence/MVP-101-*.txt`。

下一阶段可直接使用 `app.db.models` 的单数类名及 `create_database_engine()`、`database_session()`。需要变更表结构时新增迁移；不要修改已集成初始修订。策略版本不可变、状态机、账本守恒与审计只追加仍由后续任务实现并验证。
