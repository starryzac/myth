# ADR 0010：证据约束下的四级自主决策

状态：ACCEPTED / VERIFIED（2026-10-04）。前置MVP-301已通过完整验收并提交`fe0c3d6`；本项完整check通过，1122后端/4前端/1Edge及169源码集合摘要核验，见[MVP-302](../progress/MVP-302.md)。来源：[初版计划](../../../开发计划/钱途有界_初版开发计划_Codex执行版.md)8.4及MVP-302，[只读矩阵](../progress/MVP-302-preflight.md)。

## 分类和资金执行

新增纯分类器和只读服务适配器，复用301确定性财务与来源检查；分类自身不授权、不产生ActionPlan、资源预留、银行操作或回执。来源来自当前用户的正式策略、真实模拟银行事实和服务器时钟，HTTP不接受`authorized=True`、银行余额、完整worlds或客户端执行结论。

基本优先级是：来源缺失/冲突、旧动作版本、跨用户、不支持、Agent新收款意图和硬财务阻断→BLOCKED；完整已知超出持续权限→ADVISE_ONLY；确定方案需确认费用、实际金额、本人划转或需要回答用户变量→ASK_ONCE；全部条件满足→AUTO_EXECUTE。当前已有缺口但合格的恢复按301逐点不劣及改善规则判断，不能简单用baseline非READY全盘阻断。

ADVISE_ONLY不允许确认按钮扩权。无经济载荷的权限修改建议明确标记财务NOT_EVALUATED，不提供已验证金额或安全执行结论；存在具体effect却缺少财务校验的情况阻断。已知硬风险优先阻断。

正费用或正损失的赎回适配中，若可信原购买、当前版本、银行事实与精确报价全部可验证，仅存在明确的`EXECUTION_REDEMPTION_PERMISSION_DENIED`，允许在302私有的只读副本中独立计算财务后态，用于解释权限修改建议。权限结论仍为OUTSIDE_AUTHORITY，最多ADVISE_ONLY且执行资格恒false。该正成本路径的原购买身份、归属、有效期和返本对象均须已验证，且必须重新读取精确银行报价；其他缺源或财务违规仍BLOCKED。该副本不能传给301银行执行、不能落库，301原始权限门保持拒绝。原基线存在缺口而候选能按273点规则安全改善时，不因缺口本身否决这个只读建议。零成本权限失败可能早于后续自动产品/合同硬检查，因此不进入此财务副本：只可给无effect、NOT_EVALUATED的策略建议，已知基线风险优先阻断。

ASK_ONCE已经收到精确、未过期、同用户/动作/hash确认后，仍保留ASK等级和人工介入来源，只能将执行资格变为true。不能把人为确认计作无人介入的自动决策。实际执行仍由301在锁内重新验证，旧确认不能迁移到新版本、新金额或新对象。

新收款关系不在301执行协议中。Agent自行创造新目的或收款人阻断；用户主动提出但银行身份缺失或执行协议不支持同样阻断，不承诺确认后即可付款。完整已知收款关系缺持续权限可解释建议，但不能绕过来源和对象校验。

## 有限候选变量

初版只处理一个可信、完整的用户偏好变量，2至8个明确候选；当前白名单冻结为`amount_cents`，真实服务生成器只比较同一对本人现金账户的不同划转金额。来源/目标账户、对象、归属、退出约束和正式版本保持相同，仅金额及其确定性资金分配允许变化。以后增加变量必须新增明确白名单和可信生成器。不实现FULL的Minimax、多轮问题状态机、通知节流或多目标优化。银行余额、原购买证据和策略权限不能作为“用户选一种”的候选世界。

各候选独立运行确定性检查，绑定共同的已验证来源上下文摘要、用户、时间及正式版本；摘要覆盖完整银行与业务事实，不能只比较证据ID。只允许服务生成白名单用户变量变形，HTTP不接收任意候选财务快照。无法证明候选集合完整或来源相同则阻断。

有限候选的服务适配使用同一数据库上的独立只读REPEATABLE READ事务，在第一次查询前设置并验证隔离；全部候选读取同一份已提交事实。它不提交或回滚调用方事务，调用方未提交变更不能变成银行事实。不能以READ COMMITTED的“同一个Session”假定同一快照；并发写入的验证须证明本次候选一致、下次评估读取新的事实。

比较规范化经济后果签名，包括类型、金额、账户、收款、归属、原仓位、产品版本、实际返本账户、来源片段、费用/损失及到账/退出约束。排除随机operation、派生的新申购仓位ID、纯观察标记和展示收益；稳定性签名不能替代确认用effect_hash。

所有候选同一安全获授权动作，不增加询问，仍保留动作原本的成本/金额确认。可信用户变量导致动作或财务可行性分歧时，ASK_ONCE要求澄清，execution_eligible=false且不给单个可执行载荷；回答后重新准备并重验全部条件。全部候选同一硬阻断则BLOCKED。任何候选的银行缺证、旧载荷、跨用户、不支持或Agent新收款等根本门不能通过用户回答修复，仍BLOCKED。权限分歧保守建议或阻断，不能由问答扩权。

## 历史动作

对未受理原动作评估时保留原effect及精确策略版本。已银行受理/结清的操作不重新分配执行等级或重授权限；查询原银行事实和回执继续按301处理。策略撤销不抹去既有受理事实，也不释放其未知占用。

## 验证边界

四级矩阵须同时断言等级、原因、财务评估状态、当前执行资格及零副作用；包含旧版本、超权、流动性、成本、新收款人和有限候选顺序不变。纯域输入的可信前提须由真实PG适配测试验证，不能用随意构造的布尔值代替。完成实现、API合同、定向红绿、全量check及源码摘要后才能完成302并进入303。
