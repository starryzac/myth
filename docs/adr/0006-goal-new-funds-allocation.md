# ADR 0006：新增资金与月度目标候选

状态：VERIFIED for MVP-203（2026-10-04）。完整检查 `20261003T201835Z-2ff08f18` 通过，103 个源码/配置摘要一致；验证范围与限制见进度记录。前置 MVP-202 已提交 `77e788c`。来源：初版 MVP-203、7.4、链路 B；完整版 9.2–9.3；财务口径 SEM-07 与例 D。

## 范围与执行边界

初版一次指定一个 goal_id 计算月度储备候选，保留所有其他目标、义务、生活和应急约束。FULL-302 的联合词典序优化、跨目标回拨、延期与最小冲突修复不提前实现。结果是 preview_only / financial_only，不创建执行权限、资金动作或已成功消费事实。实际原子划转、来源消费、月贡献与回执、并发和重试由 MVP-301 承接。

POST /goals 只将已确认、当前有效的 goal_saving 版本关联本人现有 CASH 或 GOAL 账户，初始化新的目标归属与本月贡献为零。原账户余额、旧目标归属不变，账户已有未映射现金不能自动划给新目标。同一策略重复创建返回同一目标；不能借重试重置累计金额或改绑账户。策略修改沿用 MVP-103 的版本投影，旧目标归属继续保护。

## SEM-07：新增来源资格

新增资格只来自实际入账的 CREDIT、BANK_CONFIRMED 交易，且其绑定的银行经济角色为 INCOME。用户可编辑 category 不能决定该角色。交易发生于当前版本 max(confirmed_at, valid_from) 之后或该时点，并在服务端 as_of 前已经发生和被观察；同日更早工资不可使用。版本修改后，较早入账 lot 不隐式继承新版本资格。

旧余额、OPENING、内部划转、退款、产品本金返还和预测收入不产生新 lot。本项只接受原始入账 CASH 账户中的来源；跨账户转移不会生成新收入资格，迁移沿革与消费提交在执行账本实现时另行保留原始身份。未消费 lot 可跨自然月继续存在，月范围重置不重建来源。

受信任服务器合成导入协议 `SIMULATED_NEW_FUNDS_LEDGER / new-funds-ledger-v1` 必须声明 simulation、user_id、as_of、complete、全部当前 CASH 的 scope_account_ids 和完整 lots 清单。清单覆盖这些账户截至 as_of 的全部原生 INCOME，包括当前版本之前的旧收入；资格筛选在完整性验证之后进行。每项唯一绑定原始 transaction_id、account_id、bank_evidence_id/hash 和整数分金额，核对：

`original = spent + assigned + reserved + available`；`prior_unspent = original - spent - assigned = reserved + available`。

prior_unspent 是本快照中扣除已消费与成功归属、尚未扣在途预留的余额，不是可任意拼入的另一个历史快照。pending/UNKNOWN 必须继续 reserved，不因缺成功回执释放。逐源账户 available 合计不得超过该账户未归属目标的现金；其他账户的旧余额不能替它担保。缺完整声明、冲突、重复引用、未来事实或不守恒一律来源不足，不能默认未消费。

来源 as_of 覆盖最新采用余额时点，且和当前所选目标归属、本月贡献属于同一完整 epoch；不同账户最后余额观察时点可不同。证明必须已被服务器观察、处于有效状态且哈希与原始事实相符。HTTP 不接受客户端余额、时间、complete 或 lot 金额。

## 候选金额与边界

本月剩余 min/target/max 为原月度额度减本月已贡献并截零，各项再受总目标剩余缺口封顶。默认尽量接近 target，max 只是上限。上界 U 为 remaining_target、remaining_max、目标总额缺口及合格来源 available 之和的最小值。

目标截止日按用户本地自然日闭区间处理：当天仍可规划，超过截止日不新增贡献，既有归属继续保护。当前不可执行的未来已确认目标仍须保留在完整财务基线中；不能为了返回 INACTIVE_POLICY 而删除其未来最低约束。

按 occurred_at、origin_transaction_id 稳定 FIFO 分解来源用量。对候选 x 构造后态：来源现金账户减相应用量、目标账户加 x，合并现金不变；本目标 cash_owned/allocated 与本月 contributed 各加 x，其他归属、本金及 GOAL 未映射余额不变。同账户归属不改变账户余额。完整重算 MVP-202 的 91 日、273 检查点，不手动释放未来月份最低或优先级保障。

固定快照下目标现金增加 x，未完成最低保护的下降不快于 x，边界不会随 x 乐观增加；用整数二分求 U 内的最大安全值。baseline 来源不足或已有负余量关闭 READY 规划。最大安全值小于 remaining_min 时返回 MINIMUM_SHORTFALL，保留最低与缺口，suggested=0；可显示 max_safe 解释原因。总目标即将完成时先按总缺口封顶最低，不视为擅自修改月策略。

候选必须绑定当前目标/版本、快照、来源、金额与后态摘要。相同未变快照的预览重复得到同一候选，不偷偷消费 lot。候选过时必须重新计算；不同目标分别得到的预览不可直接相加当作联合已预留预算，301 执行前须重验和原子占用。

## 独立验收真值

例 D（分）：原现金 600000，已归属 200000，其他保护 300000，本月已贡献 100000，月范围 [150000,200000,250000]。真实工资 500000 到账后，现金 1100000；只使用该工资 lot，建议 100000，后态归属 300000、当月累计 200000、现金仍 1100000。工资剩余仍 400000。成功后的同月重算为零是因为 target 已达，不能整笔标为已消费。

同样剩余范围下，合格来源 50000 / 75000 / 200000 对应建议 50000 / 75000 / 100000；49999 应明确最低缺口 1。目标总额只差 20000 时封顶 20000。通用闲钱为零但对应当月最低已保护时，实际转成目标归属可保持边界，不重复扣除同一最低。以上需真实测试通过才能作为实现结果。

## 限制

该导入协议是合成模拟事实的信任边界，不代表真实银行提供完整资金来源追踪，也不是外部数字签名。读取预览不证明并发 exactly-once。没有来源消费明细的旧账不猜精确可分配金额；暂停、过期或未知版本不能规划新的贡献。
