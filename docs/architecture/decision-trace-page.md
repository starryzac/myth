# 决策轨迹页面（MVP-403）

页面路由为 `#decisions` 和 `#decisions/<run_id>`。使用现有决策列表、详情及原动作回执 GET；浏览轨迹不会评估、准备、确认或执行新的资金动作。列表使用服务端 opaque cursor，父子链接使用接口返回的真实 run ID。回执在用户明确点击后读取。

## 八层含义

1. 银行事实与证据：冻结副本的来源等级、原状态、观察和有效时点、声明内容及 claimed/captured 哈希。银行确认、银行观察、用户声明、模型推断分别标注。
2. 当时用户策略：原 policy/version ID、版本号、确认与有效时点、原配置声明及完整性。配置内容摘要不证明全部版本元数据或资金权限。
3. 受保护金额与约束：保存的需求、可用金额、三态满足情况、硬软约束、到期日期及计算点。原边界、预计边界、预留后边界沿保存路径区分；余量可以为负，未知值不补零。
4. 候选动作：所选阶段实际保存的候选集合、输入、结果与状态。需要一次确认或仅建议不自动等于拒绝。
5. 拒绝与限制原因：服务端依据原记录提供的说明、原代码和引用路径。可识别的引用展开对应保存分支并聚焦；定位不改变当前 hash 路由。
6. 当时自主等级：所选阶段保存的等级、财务评估、需要确认和当时确认状态。记录完整、保存状态 SUCCEEDED 与金融执行成功分别理解。
7. 当前关联动作与回执：读取时点核对的原 action、operation、request hash、receipt ID 和状态。当前成功不能替换 PREPARE 时尚待确认的历史结论；UNKNOWN 保留未完成核验含义。经济发生时点与对账时点分别展示。
8. 所选记录审计状态：使用详情顶层 `audit_chain_status`，同时展示实际保存的 input/trace hash 与算法版本。旧 explanation 的 `NOT_IMPLEMENTED` 不覆盖该结果。接口没有返回完整锚事件诊断，页面也不扩大核验范围。

## 原文和金额

`sources[].content`、`policies[].configuration` 和 legacy 原文属于声明。坏金额、坏所有者声明及其他历史错误可安全转义显示，不能转换成可信金额或参与计算。专用解析只在这些明确路径豁免金额语义；可信输入、结果、约束和候选中的金额仍严格校验。

可信金额使用 safe integer 分值和现有整数格式化器。`amount_options_cents` 为 2～8 个正整数或显式未知值；有符号余量保留符号。实际原响应文本保留数字词法，供按需核对原始大整数；解析后的声明显示不声称数字词法完整。默认 HTTP 金额 guard 保留，专用历史解析不放宽策略、目标或其他请求的合同。

集合与文本按需展开，显示已展示数量和实际总数。LEGACY_PARTIAL、UNSUPPORTED_VERSION 保留有限历史及缺口，不补造八层结论。详情或回执读取 404/409 时隐藏旧成功结果并保留错误代码，重试仍读取同一原件。

## 事务与验证

五条服务端匹配的 GET 路由在首次 DemoUser SELECT 前启用 REPEATABLE READ 与 READ ONLY：decisions list/detail/explanation、action decision/receipt。资金 POST 不匹配白名单，保留原可读写事务。

定向验证入口见 [验证映射](../spec/verification-map.md)，实际结果、原命令及来源版本见 [MVP-403](../progress/MVP-403.md)。后端测试的 `Base.metadata` 快照覆盖 23 张业务表；真实浏览器验证另核对全部 24 张物理表（含 alembic_version）。开发检查不替代初版与完整版验收节点。
