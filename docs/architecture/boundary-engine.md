# MVP-202 严格现金保护边界

依据 [ADR 0005](../adr/0005-mvp-cash-boundary.md)。纯函数位于 `app/domain/boundary.py`，公共 DTO 位于 `app/domain/boundary_types.py`：

```python
compute_boundary(snapshot, active_policy_versions, positions, products) -> BoundaryResult
```

版本为 `strict-cash-boundary-v1`。该函数只计算必要财务条件，不查询数据库、当前时间或网络，不写策略、决策或动作，不产生 `AUTO_EXECUTE` 权限。产品上限一律标明 `financial_only=true`，后续还需与授权、风险、单笔/总额及执行状态相交。

## 来源与公共合同

调用方先在同一数据库快照内验证用户归属、原始来源内容、证据级别/状态/有效期与观察时间，再提供明确事实及证据 ID。域层不把证据引用的存在当作已经访问和验证过数据库；生产来源验证由适配服务承担，纯函数测试可以使用无数据库来源的显式夹具。

| DTO | 核心内容 |
| --- | --- |
| `BoundarySnapshot` | 带时区 `as_of`、用户时区、固定 90 日跨度，以及以下事实集合和 `source_issues` |
| `CashFact` | 账户身份/类型、已记账现金和观察时间；信用卡账户余额不参与现金 |
| `BillFact` | 账单/账户身份、账单日、应还日、总额/已还额及状态 |
| `SettlementFact` | 普通周期策略 ID、`YYYY-MM`、截至快照已结清额及结清时间 |
| `GoalOwnership` | 目标/政策/可选账户身份、现金归属、本金归属及二者之和 allocated |
| `GoalMonthFact` | 目标 ID、自然月和有完整来源的本月累计贡献 |
| `LivingReserveFact` | 准确政策版本 ID、MVP-201 READY 金额和独立估算输入摘要 |
| `UnassignedGoalCash` | GOAL 账户尚未映射具体目标的现金；同样受保护 |
| `BoundaryPolicyVersion` | 最新已确认版本、规范 DSL、配置摘要、确认时间与准确有效窗 |
| `BoundaryPosition` | 持仓身份/目标归属、本金、状态和有依据的本金可用时间 |
| `BoundaryProduct` | 准确产品版本、财务条款及可选的固定无损到期规则 |

`active_policy_versions` 这个参数名沿用计划；其中也可包含已经确认但未来生效的版本。为恢复已形成的普通周期欠款，可以传入已到期版本的原有效窗。域层不因为未来窗口不再活跃而删除该窗口之前已经形成的周期义务。暂停、撤销或旧版本历史无法唯一恢复时，适配层须报告历史义务需要核验；本项不凭空创建历史债务账本。

DTO 使用严格 Pydantic 类型、禁止额外字段。金额为非负整数分，不接受布尔值或浮点数；有符号余量另用整数。输入会在公开函数入口重新验证，避免模型内部列表被后续修改绕过校验。重复账户、账单、策略、版本、持仓、产品、目标、月度贡献、同周期结清、生活估算和剩余目标账户身份均拒绝。

容量限制：100 个账户、100 个政策、100 个目标、100 个产品、10000 个持仓、10000 张账单/结清记录、1000 个目标月份。普通周期最多追溯 120 个政策月份，超限要求调用方先明确整理历史；不通过截断来漏掉更早债务。无法表示的日历范围作为输入错误处理。

## 现金、归属和独立义务

现金只来自已记账且未放入产品的账户余额，不再加目标 allocated 或持仓本金，也不扣过去已经体现在余额中的交易。域层检查目标现金和本金分解、目标本金与未结清持仓的对应关系、按账户和总体的现金归属不超余额。GOAL 账户余额必须全部映射为具体目标现金或明确的剩余目标现金。

真实账单按 `bill:{bill_id}` 形成唯一义务，金额为 `total-paid`，只计一次。账单必须关联输入范围内信用卡账户；金额/状态矛盾和日期逆序会被拒绝。未来已知应还日在本次窗口内才纳入；逾期未付在 day 0 保留并投影支付。

`bill_balance` 政策引用真实债务，不再产生一套月度付款。未出账月份不创造已有债务，不复制上期金额；`calculation_notes` 中给出 `UNISSUED_BILL_NOT_AN_EXISTING_LIABILITY`，要求新账单到达后重新计算。真实账单欠款不因对应支付政策到期而消失。

普通周期按 `policy:{policy_id}:YYYY-MM` 展开，exact 用固定额，range 用 max。短月将 `due_day` 夹到月末；周期必须在确认以后且处于版本有效窗内，不追溯确认前的假想欠款。`prepare_days_before` 是同一义务的提前准备信息；严格现金模式已经从窗口开始保护剩余义务，不据此生成第二笔扣款。

已过应还日的周期需要精确的结清事实，`paid_cents=0` 表示有来源证明尚未结清；缺记录返回不足。未来周期没有预付证明时保留完整金额。已到期版本仍可保留其有效期内已形成、经结清事实证明未付的旧周期；到期只停止新的周期生成。

## 滚动底线与目标最低

生活底线取该确认版本对应的 MVP-201 READY 结果，在本次投影有效窗内作为常量；不生成额外每日消费，不每 14 日扣一次预算。不同明确政策相加，同一政策不能重复传入旧版本。应急底线同样仅在有效窗内计入。

目标现金归属始终受保护，包括已经暂停或到期目标的既有现金。目标最低按预测窗、有效期与 deadline 相交的自然月份一次计算，首末月不按日折算：本月减去已证明的当月贡献，未来月份不预扣尚未发生的贡献。月最低总额与累计最低归属缺口取 max，再以 `max(0,target-allocated)` 封顶。

本次投影持有尚未完成的目标最低额，不虚构未来内部贡献；跨月或经过目标 deadline 不自动释放。deadline 只用于选择纳入的月份，不产生外部付款或自动撤销。只有显式 `valid_until` 停止该政策未完成的最低要求；已归属现金仍保留。新的真实贡献发生后应重新构造快照，现金归属增加、当月最低剩余减少。

## 91 个日期、273 个检查点

足够来源的结果包含本地今日 day 0 至 day 90，共 91 日，每日按顺序保留三个检查点：

1. `BEFORE_PAYMENT`：应用当日有效底线和未付需求，先检查现金。
2. `AFTER_PAYMENT`：支付当天独立义务，现金和对应未付保护同步减少。
3. `AFTER_PRINCIPAL`：加入当天有依据的本金可用事件，再检查一次。

日内有效期采取保守覆盖：政策在该日任一时段有效，该日都保留对应底线。同日本金不能提前救当天付款前的缺口。已到账或 `REDEEMED` 的本金不再次加入；没有明确可用时间的 HELD T0/T1 不编造赎回。目标本金到账时总现金和目标现金保护同额增加，不变成一般闲钱。过去的可用时点必须由适配层与当前现金/持仓状态完成对账，域层不会重复加入。

每个检查点采用：

```text
margin = cash - obligations - living - emergency - goal_cash - goal_minimum
safe_idle = max(0, minimum margin across all checkpoints)
```

缺口仍保存在有符号 `minimum_margin_cents`，`deficit_cents=max(0,-minimum_margin)`，不能截成零后称安全。顶层 `protected_cents_by_reason` 固定展示 day 0 的 `BEFORE_PAYMENT` 分层；它与全窗口最小余量可能来自不同时点，完整时点保留在轨迹中。

## 产品财务上限

无固定返还条款的产品按整个窗口持续占用计算。只有固定期限、明确结算自然日、10000 基点本金返还且不自动续作的 `FixedReturnTerms` 才生成候选返还日。上限取返还前所有检查点的最小余量；返还日也必须通过付款前/后的检查，返还从该日 `AFTER_PRINCIPAL` 才生效。

零期限也保留申购瞬间现金占用，不能跳过 day 0 的前两个检查点。若基线已有缺口，所有新增购买额度为 0；该结论不授权恢复动作，也不实现产品收益排名、起投或权限过滤。

## 输出、哈希与失败门

- `READY`：来源充分且基线各检查点无缺口。
- `LIQUIDITY_RISK`：来源充分，但有负余量；返回准确缺口和财务约束。
- `INSUFFICIENT_EVIDENCE`：源适配问题、缺现金/生活估算/目标归属或月份贡献、未知持仓、过去周期结清缺失、未来才可知的事实等。安全额度、最小余量、缺口和各产品额度为 null，不输出假精确轨迹。

矛盾的 DTO 或容量超限以 `ValueError`（含 Pydantic `ValidationError`）拒绝。来源不足与已经证明的现金缺口是不同状态。

`boundary_hash` 仅绑定算法和稳定排序后的财务输入。未来收入、预测退款、展示收益和未来利息不属于 DTO。证据 ID、原证据/来源摘要、估算审计摘要、产品条款审计摘要等审计关联字段不进入财务哈希，避免完整原证据中的未来展示字段间接改变边界。政策规范配置仍直接进入财务载荷，其摘要先验证一致。独立源摘要由服务另行返回，不能把财务哈希宣传为完整证据链哈希。

## 验证

手算测试覆盖保护义务付款守恒、滚动底线、短月和周期结清、目标最低 260000/封顶 150000、跨月保留、明确期满、当天本金先后、7 日/30 日产品差异、过期政策旧欠款、来源不足、资金归属与类型/重复校验。

逐步失败与通过输出在 `docs/progress/evidence/MVP-202-domain-*`。`MVP-202-domain-independent-regression.txt` 记录本模块与独立性质文件一起运行的结果；独立 oracle 不导入私有算法、不从轨迹反推预期，验证正额度、额度加 1 分失败、逐分枚举上限及资金守恒。最终静态检查与域测试另见 `MVP-202-domain-final.txt`。这些验证是财务必要条件证据，不表示已经实现自动资金执行。
