# MVP-203 独立目标分配账本

这里的独立预期源于初版 MVP-203、完整计划9.2–9.3、[规格审查](../spec/financial-semantics-review.md)例 D，以及 [ADR-0006](../adr/0006-goal-new-funds-allocation.md)。公开规划接口的独立验证已运行，实际结果和覆盖边界见下文。

## 边界

只验证指定单目标的新增资金规划：来源资格由可信适配层验证；纯规划读取稳定原交易身份与剩余可用额，不重建银行消费账本，也不产生真实扣款。其他目标的现金、本金与最低保护不释放。实际资金消耗、并发锁定、失败恢复和执行幂等属于 MVP-301。

同一未改变快照反复预览应产生相同计划，不消耗 lot。回执后的预览读取更新的来源剩余、目标归属及月份累计；不能为了让第二次返回零，提前把整笔部分使用的来源标成耗尽。

## 手工真值

例 D 转为整数分：原现金600000、已有目标现金200000、其他保护300000、本月已贡献100000，月范围 `[150000,200000,250000]`。工资500000真实到账后，现金为1100000，剩余月范围 `[50000,100000,150000]`，按接近 target 的规则贡献100000。

贡献后合并现金仍1100000；目标归属300000；本月累计200000；该工资来源仍有400000未使用。本月 target 已达到，所以回执后的同月重算建议0。没有新来源时，旧余额即使有金融余量也不能凭空生成新增来源。

另一个小整数例：现金25、其他保护10、目标已有现金10、本月最低5、目标10、最高15，来源可用10。当前通用闲钱为0，但已保护的5分转为目标现金时最低剩额同减，因此可分配5分；第6分会侵占其他保护。

## Oracle 独立性

测试的简化账本只处理一个明确月份、固定其他保护和已验证的来源残额；逐分枚举候选，检查现金保护和月累计/总目标上限。每分带原交易身份，按到账时间和交易 UUID 排列。它不解析策略、不调用被测规划器或边界引擎生成 expected、不读取结果轨迹反推真值。

来源分值模型给每一分分配 `(original_transaction_id, index)` 身份，以原始金额减可用额作为已消耗前缀，只枚举剩余后缀。它独立验证部分消耗后保留残额、FIFO 稳定性与同一次规划中的来源不重复使用；这是一种可验证的小账本模型，不声称银行实际上逐分编号或按此前缀协议消费。

测试调用公开接口 `plan_goal_allocation`；生产配置验证器仅构造合法输入。expected 金额由字面手算或上述逐分账本产生，不调用规划器、MVP-202 边界引擎或其私有辅助函数计算。候选返回轨迹只用于检查所有保护余量非负，不用于生成 expected。

## 已运行的验收

测试文件：[test_goal_allocation_properties.py](../../apps/api/app/tests/test_goal_allocation_properties.py)。最终一次合并运行是 **13 项 pytest 测试通过，66.95 秒**：8 项固定测试（包含参数展开），以及以下 5 组 Hypothesis 性质。

| 性质组 | 独立真值/不变量 | 本次有效生成样例 |
| --- | --- | ---: |
| 正额度最大值 | 逐分枚举最大可行额度；结果严格大于 0；下一分违反保护或来源/月 target/max/总目标上限 | 200 |
| 最低不足 | 即使旧现金充足，新来源少于剩余 min 也保持原 min；建议 0、来源用量为空、明确短缺额 | 200 |
| FIFO 与排列不变 | 仅用来源残额；相同时间按 UUID 排序；lot、账户、目标与策略输入重排后完整结果及 hash 不变 | 200 |
| 当前版本资格时点 | 当前版本确认/生效截止点包含该时刻，之前的真实收入不继承为该版本的可分配来源 | 200 |
| 月底跨月延续 | 月累计归零而原来源身份、原金额、剩余额不重建；模拟正确回执后的残额与已用分值不交叠 | 200 |

统计口径：`max_examples=200, derandomize=True, database=None, deadline=None`。上述每组最终日志均记录 `200 passing, 0 failing, 0 invalid`，合计 **1000 个有效生成测试样例**。不累加早期定向运行，不把一个样例内多次规划调用、重复预览或固定测试算入该数字；不声称 1000 个样例等于 1000 种独立生产环境。

固定测试另外覆盖例 D、来源残额身份、通用闲钱为零但最低保护转归属的可行分配、总目标将剩余 min/target/max 同时封顶，以及 CASH→GOAL、CASH→另一 CASH、同一 CASH 的三种目的账户路径。其他目标已有现金、本金及未完成最低贡献保留保护，不随所选目标的投影释放。所有金额均为整数分。

## 尚未证明的范围

简化逐分 oracle 只覆盖一个当前月份与固定其他保护；跨月性质另用明确字面输入验证来源延续，不实现第二套完整日期现金流引擎。完整未来窗口仍由 MVP-202 独立测试与候选重验覆盖。

来源证据完整性、银行字段摘要、账本 epoch、全部 CASH 流水覆盖及用户隔离属于服务/API 集成测试，不由纯 DTO fixtures 宣称已证明。跨月测试中的后续快照是假定正确回执的显式 fixture；它没有执行转账或消费来源。实际资金写入、跨请求原子消耗、并发锁定、UNKNOWN 占用恢复和执行幂等仍须由 MVP-301 证明。
