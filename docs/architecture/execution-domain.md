# MVP-301 动作财务重验

纯入口为 `revalidate_execution(effect, context, confirmation=None)`；唯一时钟是已验证的
`context.snapshot.as_of`，不读取数据库、系统时间或网络。`execution_effect_hash` 规范化集合顺序，
绑定完整不可变经济载荷。查询时间、当前边界哈希、未来收入及展示收益不进入确认哈希。

`ExecutionEffect` 和 `BankCommand` 是独立模拟银行使用的公开合同。银行自行按动作种类推导分录，
不接收任意分录列表。`ACTION_PLAN_TYPES` 将新合同 `PURCHASE_ASSET / REDEEM_ASSET`
映射为既有记录的 `ASSET_PURCHASE / ASSET_REDEEM`；不修改历史动作类型。

## 权限与确认

域只证明财务必要条件，所有结果均 `financial_only=true`。服务和银行必须独立查验当前正式权限、
收款身份、原始购买/当前资产策略、证据所有权、一次确认是否真实及已消费、业务身份与预留。
域中的确认 DTO 是服务核验后的事实，不能直接从客户端 `accepted` 布尔值构造。

内部划转与有费用或损失的赎回必须有绑定用户、operation、effect_hash、有效窗的单次确认。
周期付款关闭 `auto_execute` 时，以及所有 range 本期实际金额，也必须单次确认。
适配器从当前已确认策略构造 `requires_confirmation`，客户端不能设置该事实。
返回原因区分转账、付款、本期范围金额和成本确认，不把普通付款误标成有损动作。
准备阶段可以返回 `CONFIRMATION_REQUIRED` 及完整预计后态，不能把它解释为可执行。
改变金额、位置、归属、产品、费用或到账上界均改变确认哈希；仅执行时钟推进不会改变哈希。

赎回同时核对原购买版本及当前同一策略的正式版本、scope、资产类别、整仓单次限额、锁期、
到账延迟和本金风险等级。无成本必须双方允许 `allow_auto_recovery_without_penalty`，
且原产品允许自动、无本金波动、风险为0的确定性 T0/T1 退出；有成本必须双方允许
`allow_early_withdrawal_with_penalty`，再做精确一次确认。单次确认不能扩大原权限。
存量管理上限限制新申购，不阻止减少超额存量的赎回。人工原仓不能借当前新权限变成自动原仓。

## 五类后态

- 内部划转仅在未归属的 CASH 位置之间移动，现金总额不变；真实收入来源通过公开 IncomeUse
  精确绑定 origin 与稳定 location fragment，不从接收 CREDIT 生成新收入。银行及收入账本负责
  对全部来源位置预留、迁移或消费，不能把部分划转记作已花费。
- 周期支付同时扣现金并增加唯一账单或 policy+自然月的已付累计。`bill_balance` 仅更新实账单。
  `prepare_days_before` 不授权提前付款；只允许到期或已逾期的已知义务。
- 目标划拨重新运行 203 公共规划器，严格核对具体来源位置、原始发生时间、剩余可用额及目标目的地。
  总现金不变，目标现金、allocated、本月贡献增加实际金额；其他目标、未归属余额和本金不变。
- 申购重新运行 204 公共规划器，校验具体产品版本、条款、金额、退出时点、额度及目标引用。
  普通申购基线和预计边界均须 READY。目标申购只将该目标现金转为同目标本金，不能用通用闲钱上限
  拦截其自有现金，也不能把目标资金释放为一般资金。
- 整仓赎回绑定原仓、原产品及确切报价。净额内扣满足 `P = net + fee + loss`。
  T0 使用到账后反事实快照；T1 仅在真实执行时钟加约定结算日数后的 AFTER_PRINCIPAL 加净额，
  替换原返本事件。目标实际成本减少 allocated，本月历史贡献不回写。预计结果不冒充实际到账。

申购的 `return_account_id` 必须显式指定为真实资金来源账户之一，目标申购必须为该目标账户。
它进入经济哈希，因此排序 `cash_uses` 不会偷偷改变未来返本目的地。`purchase_exit: PlannedExit`
记录确切退出种类、请求时间和计划到账时间，并绑定原条款；仅采购允许这两个字段。
T0/T1 的计划请求尚未被银行受理，因此本次执行主预计后态中新仓
`principal_available_at=None`，须据此通过整个273点安全门。依赖该未受理回款才能安全的申购
返回 `UNACCEPTED_PLANNED_EXIT_CANNOT_SUPPORT_CASH_BOUNDARY`。原计划保留供后续决策，
不能写成银行已承诺或已到账的事实。固定到期按真实执行时间加合同期限和延迟计算，
须不晚于确认的到账上界且仍满足当前90日和目标期限；不把预览时钟伪作购买时间。

## 本期最终金额

`SettlementFact.final_total_cents` 缺省为 null，保留旧结清协议的行为。明确、可信的本期最终金额
才能替代 range 的保护上界，并须满足 `min <= final_total <= max`、`paid <= final_total`。
exact 的 final 必须与既定金额相同，bill_balance 禁止再有普通周期 final。
支付只增加实际 paid，不把未付差额伪记为已付；其他月份仍按自己的规则展开。
服务负责验证最终金额来源并将它与对应期的结清事实一起传入，不能仅信任动作请求金额。

## 预留与风险门

ExecutionContext 的预留为全部其他尚未解决的动作，排除本动作；现金预留总额包括其中目标部分。
目标预留必须由该目标真实现金支持。通用预留作为全窗现金占用；目标预留保留 C/G 成对保护，
只减少该目标可再使用的现金。AssetExposure 与资源表的重叠预留使用同一完整来源口径，不能相加
重复计数。适配器须构造两者一致的完整其他动作视图，不能把两份不相交的部分清单冒充重叠集合。

返回的 baseline/projected 是实际及本动作预计后态；reservation_adjusted_baseline/boundary
另显示其他通用预留占用后的检查结果。执行额外受现金来源及仓位占用约束。

普通配置必须保持安全；内部划转、对应义务支付不得恶化273点余量。无损恢复沿用205逐点非劣，
且至少改善一个原负点。明确有损恢复仅允许 `after(t) >= min(before(t), 0)`，且至少改善一个原负点。
这个例外只允许承担已确认成本，不允许产生新缺口、恶化原缺口或解除其他保护。

报价保持原 quote_id、定价时刻、费用、损失和期限；只要定价有效，执行时钟可推进。
域校验原报价到账与定价时刻之差等于约定日数，再以 fresh now+delay 计算实际预计到账，
且不得晚于不可变载荷中的 latest_arrival_at。不修改205原有接口或自然到期对账路径。

## 只读来源适配

`services.execution_context.load_execution_context(session, user_id, effect, now, own_action_id=None)`
使用共享边界来源、当前正式版本、全目录、资产曝光和独立银行投影建立输入，不修改数据库。
只允许排除与当前不可变 BankCommand 和 operation_id 完全一致的自身预留；另一动作不能被
冒充为自身。资源表与曝光交叉核对后，其他现金、目标现金和仓位占用保留，自身待申购仅扣一次。

已存在的收入账本即使本动作没有选择收入，也必须验证。完整旧收入 `legacy_reserved` 继续
占用现金；与无法映射的旧资产预留可能重叠时，明确要求对账，不能猜测释放或重复加减。
完全没有收入账本时允许一般现金动作，但不能凭此声称存在合格新增资金。完整但损坏的来源
会关闭执行。现金操作优先使用未归属、未预留且不属于可用新增收入的旧现金；超出部分必须
明确消费或迁移 IncomeUse，防止扣款后留下没有现金支持的可用收入资格。
