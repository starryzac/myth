# 目标创建与储备预览

`POST /api/v1/goals` 接受 policy_id、expected_version_id、account_id。必须是本人最新、已确认且当前有效的 goal_saving 策略，关联账户须属于本人并且类型为 CASH 或 GOAL。接口不接收新策略配置、已有归属金额、工资或客户端时间；策略创建和明确确认使用已有编译/确认流程。

创建只增加 Goal 与两份合成初始事实：归属 0、本月贡献 0。账户余额不变，不认领目的账户原有未映射现金，不移动其他目标归属。证明标明服务器生成的模拟初始状态，不声称来自真实银行接口。已有账户不是新建账户，余额观察时点保持，因此初始化不会凭空推进全用户的资金流水。

以 policy_id 锁定创建，目标身份确定、每策略唯一。重复相同请求返回现有目标，不重置已累计金额、不再创建初始证明。改变目的账户返回 GOAL_ACCOUNT_CONFLICT；过时版本返回 VERSION_CONFLICT；暂停/到期/撤销或缺有效确认证据不能创建。目标策略修改继续通过 MVP-103 更新已有 Goal 配置，既有归属不因改目标金额而自动回收。

`GET /api/v1/goals` 返回本人目标投影。`GET /api/v1/goals/{goal_id}/allocation-preview` 使用服务端身份、时间与一致数据库快照，并读取已经验证的来源证明；不接收额外查询参数。预览结果含 allocation、来源引用和摘要；资金来源不足时金额为空，不把未知可用额度显示为零。

预览不会写来源消费或资金记录，不能把分别预览的多个目标金额相加当作已经预留的联合额度。实际执行、逐来源原子消费和并发争用留 MVP-301。原始 404 失败和后续真实 PostgreSQL 验证见 `docs/progress/evidence/MVP-203-goal-*`；本项完整质量门尚未运行。
