# 资金总览与外部银行事实

`GET /api/v1/dashboard` 使用可信演示用户和服务端时钟，在用户首次读取前建立同一个 REPEATABLE READ / READ ONLY 事务。它不接受客户端金额、账户、用户或时钟。只有列表数量参数，未知参数拒绝。全部卡片来自该快照，查询不创建决策、动作、预留、回执或金融事实。

原 `financial-v1` 边界与新增展示明细共享一次纯计算。原窗口摘要和 hash 保持兼容；今天的保护金额与 91 日窗口限制日分别展示。下一组义务使用原到期日，保留同日项目、区间、逾期状态。未来收入不能扩大今天的安全资金。金额未知返回 null；前端显示“待核验”，不能补成零。

账面现金包含目标账户现金。目标归属区分现金、本金与待归属的目标账户现金；已自主配置只统计具有完整授权和来源位置的当前本金，排除手工持仓、预期收益和待买入本金。目标本金可能已经包含在自主配置中，两者不能相加。资金边界是金融条件，正金额不会直接授予执行权限。

读取复用本次完整资金上下文：同用户、同时间、所有来源范围的完整曝光与一次当前审计 epoch 核验。每条待执行动作另查其原执行锚点；限量列表报告 total/has_more，不把未读内容宣称完整。对账待定优先于确认、复核；历史恢复提议不能替代当前具体确认。输入数量与字节预算在完整加载前检查，不能截断金融来源后求和。

外部工资和普通消费由可信内部模拟 runner 提交，公众页面不提供伪造资金事实的按钮。`bank-external-fact-v1` 绑定用户、来源、external_ref 和原首个幂等键。重复事实换新键返回冲突；同键改变原件也拒绝。同一原件重放只查询已有银行事实或补应用投影，不重复现金经济腿。

银行接受事实后以独立事务落两条守恒经济分录；应用事务更新账面、收入位置和审计原件。投影失败时银行仍 SETTLED、应用为 UNKNOWN。恢复沿用原事实及原键。消费按已证明可用收入 FIFO，再用已证明的未跟踪现金；不得释放目标现金、目标本金、收入 claim 或执行预留。保护侵入时应用投影完整回滚，UNKNOWN 留待对账。

0007 增加外部事实表和 posting 的可空 external_fact_id。旧 18 字段分录仍使用原 v1 字节；外部/CLEARING 分录明确使用 v2。原用户、原对象与来源 XOR 约束、不可变原件和提交时两腿守恒在数据库验证。审计外层 canonical 协议不变，新增外部事件 payload v2 有独立注册与验证，不静默转换旧原件。

验证按[最小验证集](../spec/verification-map.md)执行；任务证据在[MVP-401](../progress/MVP-401.md)。单次页面查询耗时与有 profiler 的测试耗时分别记录，不将其当产品 SLA。
